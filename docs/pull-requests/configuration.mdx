# Pull Requests Configuration

For the versioned `PR_APPROVAL_POLICY` Variable, setup defaults, producer tuples, coverage modes, and safety limits, see [guarded PR approval](/pull-requests/guarded-approval). A missing Variable means off in existing installations; a new `copilot setup` plan proposes recommendation-only assessment and requires an explicit choice and producer attestation before guarded native approval.

These inputs apply when the action runs on `pull_request` events. For the complete list of all action inputs, see [Configuration](/configuration).

## Project and assignees

| Input | Description | Default |
|-------|-------------|---------|
| `project-ids` | Comma-separated GitHub Project IDs to link PRs to | — |
| `project-column-pull-request-created` | Column for newly created/linked PRs | "In Progress" |
| `project-column-pull-request-in-progress` | Column for in-progress PRs | "In Progress" |
| `desired-reviewers-count` | Number of reviewers to assign (max: 15) | 1 |

## AI (PR description and comments)

| Input | Description | Default |
|-------|-------------|---------|
| `ai-pull-request-description-mode` | `replace`, `append`, `preserve`, or `disabled`; controls automatic ownership and explicit `/copilot description` updates | `replace` |
| `repository-locale` | BCP-47 locale inherited by generated repository, issue, and PR messages | `en-US` |
| `pull-requests-locale` | Optional PR-surface override; empty inherits `repository-locale` | empty |
| `ai-members-only` | Restrict AI PR description to org/project members only | "false" |

See [AI PR description](/pull-requests/ai-description) for how the description is generated and [Agent CLI configuration](/agents/cli-configuration) for runtime and model setup.

Copilot preserves the original review comment byte-for-byte. For an addressed request in another language it performs one bounded adaptation before domain work, keeps commands and technical operands intact, and adds escaped translation context to the bot-owned response only when translation occurred.

## Other

| Input | Description | Default |
|-------|-------------|---------|
| `commit-prefix-transforms` | Transforms for commit prefix from branch name (e.g. `replace-slash`) | "replace-slash" |
| `token` | GitHub PAT (required for linking and project updates) | — |
| `emoji-labeled-title` | Label-based issue titles and conventional linked PR title generation; an existing conventional PR title takes precedence | "true" |

For size thresholds, priority labels, and branch naming (used when the action infers the issue from the branch), see [Configuration](/configuration).

See [PR title precedence](/pull-requests/workflow-setup#pull-request-title-precedence)
for generated prefixes, author corrections and migration from decorated titles.
Setting `emoji-labeled-title: "false"` disables both issue and PR title automation
when your repository uses another title convention. There is no separate title
format input; the consumer's semantic-title check remains authoritative.

## Fixed linkage safety rules

PR-link recovery is intentionally not configurable. Repository identity and the
PAT are bound by the action runtime; capability requests contain neither. PR and
issue numbers must be positive safe integers, branch refs must be safe, and the
provider target is derived from the configured repository rather than an event
URL. The temporary marker format, default-branch observation delay, compensation
order, and owned-reference cleanup cannot be weakened by workflow inputs.

Linkage inspection uses the configured token with GitHub GraphQL
`closingIssuesReferences`; it never requests a public HTML page. Private and
public PRs follow the same path. The exact repository, PR and intended issue
must match; a link to another issue or repository does not skip linkage. Reads
are fixed at two pages of 100 references. Incomplete or malformed evidence stops
the operation rather than claiming the PR is unlinked.

If inspection fails before temporary edits, the current base and description
remain unchanged. An interrupted owned operation still attempts compensation.
`authorization.credential-invalid` and `authorization.denied` require checking
the documented credential access (including GraphQL `UNAUTHORIZED` and
`FORBIDDEN` responses); `provider.not-found` requires checking the PR
identity and credential visibility. `configuration.unsupported` requires a
supported installation; `provider.contract-invalid` requires integration review
(including the fixed reference limit). Rate limits and transport outages retain
their retryable diagnostics. Inspect the run's retained-state guidance before
retrying an interrupted operation. No additional permission is introduced.


A later `opened`, `reopened`, `synchronize`, `ready_for_review` or eligible
`edited` invocation repairs an interrupted pending link before ordinary work.
Recovery uses the recorded original base, even if the new event sees the temporary
default base. It verifies native PR/head repository/ref ownership and the exact
operation, restores and verifies the original base, then removes only its own
reference and marker. Concurrent prose and configuration remain intact.

Interrupted recovery from a body record requires a native same-repository head.
Foreign-head pending records retain evidence for maintainer inspection; a body
marker cannot grant retarget authority. Fresh fork linkage can still compensate
its own operation in the same invocation.

The pending original parent takes precedence over the mutable target when loading
configuration. Stale invocations and blocked linkage do not persist configuration;
a temporary target cannot silently replace the recorded `parentBranch`. Failed or
unverified restoration retains pending evidence. Rerun the current PR workflow
after a transient failure. Inspect identity/base/operation conflicts when recovery
remains blocked; do not delete the marker to silence the failure.

Existing V1 pending records remain recoverable. New V2 records bind the native
head repository/ref and an operation ID. Finish or reconcile pending V2 recovery
with the newer runtime before rolling back to a runtime that cannot read V2.
No input, storage backend or extra credential permission is required.
