# Agent execution contract

A run resolves one complete structured selection before invoking a CLI:

```text
runtime = agent-provider
model = agent-model-provider/agent-model
effort = agent-effort (optional)
executable = agent-executable or the runtime manifest basename
```

The selection is invalid when a required value is empty, malformed, outside an allowlist, or inconsistent with the runtime. Callers cannot provide command text, subcommands, flags, environment prefixes, wrapper scripts, response files, or raw argv. There is no compatibility path for those shapes.

Every lifecycle role may override the selection independently with `planner-*`, `findings-*`, `reviewer-*`, `fixer-*`, or `tester-*`. Empty fields inherit the common selection. Inactive roles are neither authenticated nor provisioned.

| Role | Responsibilities | Workspace mode |
| --- | --- | --- |
| `planner` | Help, recommendations, descriptions, plans, and answers | Read-only |
| `findings` | Push analysis, progress, context review, and classification | Read-only |
| `reviewer` | Pull-request Bugbot analysis and review commands | Read-only |
| `fixer` | Explicitly authorized file changes | Workspace write |
| `tester` | Test-plan commands | Read-only |
| language capability | Comment translation and language analysis | Read-only |

The runtime creates one complete `AgentExecutionPlan`. A compile-time exhaustive dispatcher calls an independent policy for Codex, OpenCode, or Cursor. The policy reconstructs all argv and default-deny provider configuration. Preflight then verifies the canonical repository root, executable ownership and permissions, non-empty CLI identity, managed artifact hashes, hard limits, and secret-safe environment before `spawn` is possible.

All roles deny agent-tool network, approval escalation, MCP, plugins, subagents, session persistence, Git credentials, and ambient repository/user provider configuration. Only `fixer` receives workspace write access; trusted Copilot code remains responsible for validation, commit, push, publication, and GitHub mutation.

Codex child commands retain only a fixed list of system variables: `PATH`,
`SystemRoot`, `WINDIR`, `PATHEXT`, `TMPDIR`, `TEMP`, `TMP`, `LANG`, and `LC_ALL`.
These let the sandbox locate its system tools on Linux and Windows. Model,
GitHub, Git, SSH, proxy, and home/configuration variables are excluded. The
list is fixed by Copilot and cannot be expanded through repository inputs.

The hard maxima are 15 minutes, 512 KiB of prompt bytes, and 4 MiB of combined process output. Structured tasks declare a JSON Schema. Before Codex starts, Copilot requires a closed object schema in which every property is required, optional values are nullable, nested objects reject additional properties, and arrays define their items. Copilot then validates the returned response locally as well. An incompatible contract, invalid or oversized output, and prose-wrapped JSON are rejected; removed response shapes have no legacy conversion path.

For Codex, the native schema preserves that closed JSON shape while string
length bounds are enforced locally from the complete original schema. This
provider compatibility projection also covers nested and nullable strings;
it does not change numeric/array bounds, required fields or local acceptance.

Every product-facing read-only task also receives the canonical effective
`targetLocale` and must return the exact same tag in required `outputLocale`
metadata. This covers Think and help answers, recommendations, progress,
pull-request descriptions, and Bugbot findings. A missing, malformed,
non-canonical, or different output locale is rejected before a comment, review,
description, label, or recommendation state can change. There is no
best-effort mixed-language publication. Technical paths, refs, commands, links,
identifiers, and structured facts remain locale-independent.

Each invocation emits bounded lifecycle observations for plan start, admitted
preflight, and terminal execution. They include only provider, capability,
manifest/version, workspace and output modes, artifact hashes, duration, byte
count, and semantic result category. Prompts, response content, model names,
argv, environment values, paths, raw stderr, and user identity are excluded by
the observer contract.

The reviewed runtime baseline is Codex `codex-cli 0.156.1`, OpenCode `1.18.3`, and Cursor Agent `2026.09.10-fd3934a`. An available runtime may report any non-empty version and is never silently replaced; an incompatible command surface fails terminally with no provider fallback. See [Agent input reference](/agents/input-reference) and [Agent failure policy](/agents/failure-policy).

When a run rejects process output, its log includes a fixed local cause: `output-limit`, `empty-output`, `malformed-json-event`, `invalid-json-event`, `missing-text-events`, or `unclassified`. These codes distinguish the existing rejection paths without exposing the response or prompt. Inspect the code before retrying or changing a provider integration; a historical log that only says `run/output` cannot establish the cause.

A failed CLI process can report `reported-output-token-limit` when the provider
cuts off generation before completing its response. This differs from Copilot's
combined output-byte limit or request timeout. Failure classification checks a
bounded last 8 KiB of stderr before the existing first 8 KiB, so a long prompt
cannot hide a terminal diagnostic. Only a fixed hint is logged; neither window
is published. The hint does not authorize an automatic retry or a settings change.

## Codex service-runner support

**Codex no soportado en runners Windows ejecutados como servicio.** Codex jobs
use the macOS/Ubuntu pool; Windows service registrations omit `codex`. Retained
Windows policies and fake ACL/process fixtures do not certify real Codex
integration. An authenticated model reply or CLI exit 0 can accompany failed
tools. Tool acceptance requires a verified repository read/edit or command and
trusted postflight. See [Codex runtime support](/agents/codex-openai).

## Windows startup evidence

Maintainers of this repository can dispatch the `Setup Platform Smoke` workflow
with `windows_startup_probe=true` to compare bounded PowerShell startup in the
isolated ACL environment and the runner baseline. The report contains only
closed statuses and elapsed milliseconds. This read-only investigation does not
replace the required runtime fixtures or certify a successful agent execution.


The ACL descriptor probe imports the trusted absolute Windows system Utility
manifest before JSON serialization, with automatic module loading disabled.
This avoids discovery scans when the module analysis cache is disabled. The
probe still uses its fixed minimal environment, complete file/ancestor batch,
DACL policy and original timeout. No profile, credential, ambient module path
or writable repository cache is inherited. General hosted Windows platform fixtures remain required for those native
process and ACL contracts. Codex integration fixtures run only on macOS and
Ubuntu; they do not certify a Windows service sandbox.

Progress assessments receive a complete comparison pinned to the repository's
base and source commits. Generated `build/` outputs and the exact generated
`specs/CATALOG.md` index contribute file facts only; the editable catalog JSON
still contributes its full source patch. These generated facts never certify a
build or test. Comparisons exceeding the existing 256,000-byte evidence budget
remain unavailable and preserve progress state. That condition does not imply
that the branch changed during the invocation.
