# Agent failure policy

The Action fails closed. It MUST stop rather than silently selecting another runtime, provider, model, credential, or transport.

| Failure | Phase | Required behavior |
| --- | --- | --- |
| Unsupported runtime | Configuration | Stop before CLI execution |
| Empty model | Configuration | Stop before CLI execution |
| Invalid model provider | Configuration | Stop before CLI execution |
| Provider not allowlisted | Authorization | Stop before CLI execution |
| Qualified model not allowlisted | Authorization | Stop before CLI execution |
| Preinstalled runtime returns empty identity | Preflight | Stop before agent process |
| Official installer fails or returns an empty version | Provisioning | Stop before agent process |
| Missing executable | Provisioning | Stop before agent request |
| Missing credential reference | Authentication preflight | Stop before agent request |
| Executable owner/permissions invalid | Preflight | Stop before agent request |
| Workspace is not the canonical repository root | Preflight | Stop before agent request |
| Managed artifact hash changes | Preflight | Stop before agent request |
| Windows npm shim or bin cannot be resolved safely | Preflight | Stop before agent request; do not invoke a command shell |
| Managed Windows ACL is not owner-only | Preflight | Stop before agent request; do not trust process output |
| Ambient provider configuration exists | Preflight | Stop before agent request |
| CLI timeout | Execution | Stop; do not switch provider |
| Windows process-tree termination fails | Execution | Fail the capability; inspect runner descendants and cleanup before retry |
| Non-zero CLI exit | Execution | Stop; preserve sanitized diagnostics only |
| Invalid agent response | Parsing | Stop; do not publish unsafe findings |
| Missing or mismatched `outputLocale` | Parsing | Stop before product publication or state mutation; retain existing state |
| Verification command fails | Autofix | Do not commit or push |
| Sensitive workspace change | Commit policy | Reject automated commit |

## Retry rule

Retries, when implemented by a provider-specific policy, MUST retry only the same selected operation. A retry MUST NOT change the runtime, provider, model, credential, executable, or admitted plan.

## Logging rule

Lifecycle diagnostics include only bounded semantic observations: provider,
capability, phase, manifest/version, authority/output modes, artifact hashes,
duration, output byte count, failure category, semantic code, and retryability.
They MUST NOT include model names, API keys, OAuth tokens, authentication files,
cookies, prompts, response content, argv, paths, environment values, raw stderr,
or user identity.

A completed CLI observation may carry the closed provider-reported hint
`reported-sandbox-setup-mutex` from the first 8 KiB of stderr. The log distinguishes
process completion from the reported sandbox tool failure. This hint does not
change the process result, authorize a retry or certify capability success.
Model prose and unknown or truncated provider text are not diagnostic evidence.

Nonzero exits also inspect a separate last-8-KiB stderr window before falling
back to the first window. The exact CLI terminal output-token-limit line maps
to `reported-output-token-limit`; response content, raw stderr and prompts stay
private. That failure still stops the capability. For SDD drafting, use the
[compact generation and recovery guidance](/issues/pre-branch-sdds#draft-validation-recovery)
before rerunning the same issue; changing tokens or permissions does not address
a provider output-token limit.

## Cost rule

A real provider request MUST be authorized before execution when it can incur usage charges or consume plan quotas. Binary/version/help checks are not evidence of successful model authentication.

## Security rule

Credentials MUST NOT be available to untrusted forks or attacker-controlled code. `pull_request_target` MUST NOT check out and execute untrusted code in a credentialed job.
