# Codex and OpenAI

## Status

<Warning>
The repository does not include a Codex credential. A controlled self-hosted runner may provide a preinitialized Codex session; otherwise map `CODEX_API_KEY` as a secret. Authenticated provider smoke tests must be run by the operator with an authorized account.
</Warning>

Copilot separates two concepts:

| Concept | Configuration | Meaning |
| --- | --- | --- |
| Runtime | `agent-provider: codex` | Executes the external `codex` CLI. |
| Model provider | `agent-model-provider: openai` | Identifies the provider serving the selected model. |
| Model | `agent-model` | Names the model without the provider prefix. |

Do not describe `codex` and `openai` as interchangeable values. `codex` is a runtime; `openai` is a model/authentication provider.

## Windows runners executed as a service

**Codex no soportado en runners Windows ejecutados como servicio.** Run Codex
jobs on macOS or Ubuntu. This limitation concerns unattended Windows services
in session 0, not every Windows environment. The same account and managed
configuration succeeded in an interactive session during the operator's
2026-10-12 reproduction.

The official CLI, including 0.162.1, could authenticate and answer the model
while tool startup failed with `0xc0000142` and a command-runner pipe timeout
under `--strict-config`, `--ignore-user-config`, and
`windows.sandbox="elevated"`. Official setup did not resolve the service failure.
A successful CLI exit or model response therefore does not certify repository
reads, edits, or command execution. Tool acceptance requires an actual bounded
read or write, its verifiable result, and trusted post-execution checks.

This repository retains `[self-hosted, codex]` for the shared macOS/Ubuntu pool.
Windows service registrations MUST omit `codex`; existing registrations MUST
lose that label when recreated. Windows services remain available for other
jobs. Remove explicit Windows Codex matrix entries instead of leaving jobs
queued for an unavailable runner. General hosted Windows coverage and fake
platform-safety fixtures remain; they do not execute or certify real Codex tools.
Do not deploy a community CLI build, disable the sandbox, or convert these
services into interactive sessions to work around this limitation.

## CLI runtime

The built-in Codex command is:

```text
codex exec --strict-config --ignore-user-config --ignore-rules --ephemeral --sandbox <mode> --model <model> --config 'model_provider="<provider>"' [--config 'model_reasoning_effort="<effort>"'] -
```

The command reads the prompt from standard input, runs ephemerally, and does not use a shell. A provider failure is terminal; Copilot does not silently fall back to OpenCode or Cursor.

## Authentication modes

Codex can use one of the following credential references:

| Mode | Reference | Scope |
| --- | --- | --- |
| Codex API key | `CODEX_API_KEY` | Official per-invocation automation credential; programmatic/API billing. |
| Local ChatGPT session | Local Codex authentication state | Controlled self-hosted runner only; never export it to hosted CI. |

Copilot never prints, copies, or serializes token values. With no exported credential, preflight executes the configured Codex binary's `login status` command with a bounded timeout and fails closed unless it succeeds. When a local ChatGPT session is detected, the Codex child process does not receive exported Codex/OpenAI credentials, preventing them from overriding the local session. Official Codex guidance confirms that `codex exec` reuses saved authentication and documents `CODEX_API_KEY` for scoped automation; see [non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode) and [Codex authentication and compliance](/security-operations/security/authentication-compliance).

## Provisioning

GitHub Actions reuses an available `codex` executable. If the default command is missing, the Action runs the [official OpenAI standalone installer](https://learn.chatgpt.com/docs/codex/cli) in a private job directory, without npm or pnpm. It does not require an exact version; the resulting CLI must report a non-empty version and pass the normal guarded preflight. An explicit executable path is never replaced.

Verify the executable before a real request:

```bash
codex --version
codex exec --help
```

## Configuration example

```yaml
with:
  agent-provider: codex
  agent-model-provider: openai
  agent-model: gpt-6-luna
env:
  AGENT_ALLOWED_MODEL_PROVIDERS: openai
  AGENT_ALLOWED_MODELS: openai/gpt-6-luna
  # Omit when the controlled runner is already authenticated.
  CODEX_API_KEY: ${{ secrets.CODEX_API_KEY }}
```

The allowlists are policy controls. They do not create credentials, and they do not make a ChatGPT session suitable for hosted CI.

## Verification boundary

A help command proves only that the binary is available. It does not prove authentication, model entitlement, quota, billing, or permission to use a personal ChatGPT session in CI. Run a real smoke test only with explicit authorization, a bounded cost, and read-only instructions. A model-only reply proves neither a sandbox command nor successful tool execution.
