# Runtime selection

`agent-provider` selects the executable runtime:

| Value | Executable | Input mode |
| --- | --- | --- |
| `opencode` | `opencode` | One positional prompt, explicit `--model` |
| `codex` | `codex` | Ephemeral stdin execution |
| `cursor` | `agent` | Non-interactive prompt mode |

Only runtimes selected by active roles are provisioned, authenticated, and executed. A workflow may therefore use more than one runtime when its active roles have independent overrides. The runtime is not the model provider. For example, `opencode` can execute an `openai/...` model.

`agent-executable` and the corresponding role overrides may select only the expected bare basename or an absolute path with that basename. The canonical target must be a regular executable owned by the runner user or root and not group/world writable. The runtime manifest records reviewed identities and pinned installation recipes. An available operator-owned runtime may report another non-empty version and is never replaced; exact matching applies only after Copilot installs a missing default Codex or OpenCode package.

There is no runtime registry or provider fallback. The exhaustive dispatcher recognizes exactly these three values and rejects every other value before spawn.
