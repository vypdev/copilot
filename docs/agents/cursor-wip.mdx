# Cursor runtime

<Warning>
The Cursor CLI integration is complete at the code and provisioning boundary. A real authenticated smoke test remains an operator responsibility because this repository does not yet have a `CURSOR_API_KEY`.
</Warning>

## What is implemented

Copilot has the provider-specific CLI shape:

```text
agent -p --output-format text --model <model> <prompt>
```

The Action can provision the official Cursor installer when all required inputs are present:

```text
CURSOR_INSTALLER_SHA256
CURSOR_API_KEY
```

The installer checksum is verified before execution. Unofficial npm packages, shell fallbacks, and unverified downloads are not supported.

## Operator validation still required

- authenticated end-to-end smoke test with an authorized `CURSOR_API_KEY`;
- confirmation that the installer remains compatible with the operator's runner image;
- review of Cursor-specific billing and account restrictions for the selected workspace.

The deterministic adapter, timeout, cancellation, output-limit, and terminal-failure behavior is covered by repository tests. The absence of a Cursor credential only prevents an authenticated smoke test; it does not prevent configuration or provisioning checks.

## Configuration shape

```yaml
with:
  agent-provider: cursor
  agent-model-provider: cursor
  agent-model: <approved-model>
  agent-effort: <optional-preference>
env:
  CURSOR_API_KEY: ${{ secrets.CURSOR_API_KEY }}
```

The runtime provider (`cursor`) is separate from the model provider and model. Cursor's documented CLI exposes model selection but no standard effort flag; Copilot keeps the common effort value in the execution context instead of inventing an unsupported CLI option. Do not assume that a CLI installation proves that a selected model is available or authorized.

## Security boundary

Never put `CURSOR_API_KEY` in action inputs, command arguments, prompts, repository files, or logs. Use a protected runner environment and do not expose the credential to fork-controlled code.

## Current verification commands

These checks are safe binary checks only:

```bash
agent --version
agent --help
node scripts/verify-agent-clis.cjs
```

They do not replace the pending authenticated smoke test. Do not run that test without explicit authorization, a bounded cost, and a read-only prompt.
