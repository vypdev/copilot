# Agent input reference

The agent inputs are the public configuration contract for agent execution. Provider-specific capabilities not represented by the common contract can be supplied through an audited `agent-command` override.

## Selection inputs

| Input | Required | Effective default | Meaning | Secret |
| --- | --- | --- | --- | --- |
| `agent-provider` | No | `codex` | CLI runtime: `codex`, `opencode`, or `cursor` | No |
| `agent-model-provider` | No | `openai` | Provider serving the selected model | No |
| `agent-model` | No | `gpt-5.6-luna` | Model name without the provider prefix | No |
| `agent-effort` | No | empty | Reasoning effort or provider-specific model variant | No |
| `agent-command` | No | Provider-specific command | Optional literal CLI override | No |

Each task also supports independent overrides: `findings-provider`, `findings-model-provider`, `findings-model`, `findings-effort`, `findings-command` and the corresponding `fixer-*` inputs. The lifecycle roles `planner-*`, `reviewer-*`, `tester-*`, and `release-*` are optional overrides for planning/conversation, PR review, test planning, and release planning. Empty role overrides inherit the common selection. The built-in mapping is `findings` for push Bugbot, `reviewer` for PR Bugbot, `planner` for plans and answers, and `fixer` for authorized file changes.

The qualified model is always constructed as:

```text
<agent-model-provider>/<agent-model>
```

For the effective defaults:

```text
openai/gpt-5.6-luna
```

## Authorization variables

| Variable | Example | Meaning |
| --- | --- | --- |
| `AGENT_ALLOWED_MODEL_PROVIDERS` | `openai` | Comma-separated provider allowlist |
| `AGENT_ALLOWED_MODELS` | `openai/gpt-5.6-luna` | Exact qualified-model allowlist |

Allowlists authorize a selection. They do not select the runtime, model, or credential.

## Authentication variables

| Runtime/provider | Credential reference |
| --- | --- |
| OpenCode using OpenAI | `OPENAI_API_KEY` or a controlled local provider login |
| Codex | `CODEX_ACCESS_TOKEN`, `OPENAI_API_KEY`, or a controlled local Codex session |
| Cursor | `CURSOR_API_KEY` |

Values MUST be supplied through the runner's secret/environment mechanism. They MUST NOT be placed in `with`, command arguments, prompts, repository files, or logs.

## Provider commands

| Runtime | Default command |
| --- | --- |
| OpenCode | `opencode run --model <provider>/<model> [--variant <effort>]` |
| Codex | `codex exec --ephemeral --skip-git-repo-check --model <model> --config 'model_provider="<provider>"' [--config 'model_reasoning_effort="<effort>"'] -` |
| Cursor | `agent -p --output-format text --model <model> <prompt>` |

Commands are executed without a shell. Codex receives the prompt over `stdin`; OpenCode and Cursor receive it as a single positional argument. A custom command MUST contain explicit model selection; Codex must also contain `model_provider`, and Codex/OpenCode must contain effort when configured. No runtime, provider, model, credential, or command fallback is attempted.

## Configuration ownership

- Action inputs are declared in `action.yml`.
- Workflow defaults are declared in `setup/workflows/*.yml`.
- Runtime input resolution is implemented in `src/actions/agent_input_builder.ts`.
- Model authorization is implemented in `src/actions/agent_configuration_builder.ts`.
- Provider commands are implemented in provider-specific CLI adapters.

A change to one source MUST be reflected in the others and covered by validation.
