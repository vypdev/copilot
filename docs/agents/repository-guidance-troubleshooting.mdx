# Repository guidance troubleshooting

Run the read-only diagnosis with the same expected configuration used by setup:

```bash
copilot doctor --config copilot.setup.yml
```

The named checks cover the manifest, profile schema and runtime parity, guide digest, skill contract, discovery pointer, enabled forms, and release/hotfix workflow files.

| State | Meaning | Safe response |
|---|---|---|
| pass/current | generated bytes, hashes, and expected config agree | no action |
| reduced discovery | guide and skill are valid but no managed root pointer exists | optionally rerun setup with `agentsPointer: prompt` |
| drifted | a hash-owned file changed after setup | review the change, preserve it, then explicitly reconcile |
| unowned conflict | a desired path existed without valid ownership evidence | move or merge it deliberately; setup will not overwrite it |
| malformed markers | only one pointer marker, duplicates, or nesting exists | repair markers manually; setup preserves the file |
| stale profile | profile/guide/skill describe another setup selection | rerun setup with the intended config |
| missing form/workflow | an enabled profile fact has no matching installed asset | rerun setup or restore the asset from backup |

Setup writes each generated artifact atomically and the manifest last. Approved replacements and retirements are copied or moved under `.copilot/setup-backups/`. If a run stops before the manifest advances, rerun with the same configuration: desired bytes are recognized, while unrelated or drifted bytes remain untouched.

Do not repair drift by editing `.copilot/repository-profile.json` or its hashes. Change the setup configuration and rerun setup so forms, Variables, workflows, guide, skill, and manifest converge from one plan.
