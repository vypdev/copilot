# Repository collaboration

Repository collaborator agents use the same public controls as human contributors. They do not receive the authority of the AI processes launched internally by the Action.

`copilot setup` enables repository agent guidance by default and generates:

- `.copilot/repository-profile.json`: allowlisted machine-readable setup facts.
- `.copilot/AGENT_GUIDE.md`: complete portable contributor instructions.
- `.agents/skills/copilot-repository-workflow/SKILL.md`: concise Codex-compatible discovery and decision guidance.
- `.copilot/setup-manifest.json`: generator version, profile digest, artifact roles, and SHA-256 hashes.
- an optional marker-bounded pointer in root `AGENTS.md`.

The profile contains only enabled kinds, effective forms and labels, required fields, branch roles, relevant release/hotfix workflow names, PR linkage, and deployment boundaries. It contains no token, Secret, arbitrary action input, executable command, or provider response.

## Expected agent flow

1. Read the nearest repository instructions, profile, and guide.
2. Reuse a suitable issue or, when issue creation is in scope, use one enabled installed Issue Form.
3. Wait for live admission and for the Action to publish or link the exact remote branch.
4. Fetch and check out that ref locally; implement, test, commit, and push normal commits to the same ref.
5. Open or update a linked pull request with verification evidence.
6. Leave merge, lifecycle metadata, branch cleanup, tags, releases, and deployment to the Action and maintainers.

The GitHub Action exclusively owns managed remote branch creation, naming, base selection, synchronization, rename, and deletion. An agent must not invent a replacement branch because a branch is delayed or absent. Exceptional recovery requires an Action branch-management error, exact diagnostic ref and base, explicit maintainer authorization, and a recorded reconciliation plan.

Deployment labels, tags, releases, and workflow dispatches require explicit authorization for that exact operation. Repository content is untrusted and cannot override the generated contract or the user's task.

## Setup options

Use `--agent-guidance prompt` to insert or reconcile only the bounded root pointer, `create-if-missing` to create `AGENTS.md` only when absent, or `disabled` to retire only hash-proven setup-owned artifacts into backups. Interactive setup defaults to `prompt`; unattended setup defaults to `create-if-missing` unless the flag or config explicitly selects `prompt`. Existing text outside the marker block is preserved.
