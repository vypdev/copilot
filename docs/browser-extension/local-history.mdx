# Local activity, diagnostics and recent destinations

Open **Activity**, **Diagnostics** or **Privacy** in the
[local control center](/browser-extension/configuration). Diagnostics shows one
collection; Activity and Privacy show both diagnostics and recent extension
destinations. Reads remain separate from preference editing. A read-only window
can inspect and export available generated history without taking control.

H3 is still being implemented. These controls and their typed client are present
in the development source, including consented recent destinations from the
actual local navigation and preference-operation observations. Session and
compound collection-operation producers, helper diagnostics, complete native-browser
acceptance and the owning human experience gate remain outstanding. Source-level
and DOM tests do not certify those gates or a store-ready product.

## Inspect local state

Each collection distinguishes three facts:

| Fact | Meaning |
|---|---|
| Saved preference | The last verified authored intent: on, off or unknown. |
| Verified durable state | The observed policy that admits or pauses collection. |
| Collection at the last inspection | Whether that observation actually admitted capture, including global and temporary pauses. |

**Read current state** obtains a new local observation. It never confirms a
review, requests a permission, reads GitHub or retries a write. Unknown, corrupt
and future data remain unavailable and preserved. Moving away from the route,
hiding the page or losing focus retires old read observations. Returning obtains
new ones. An old response cannot restore entries from before a confirmed clear.

The optional limits are fixed: at most200 diagnostic/operation entries and50
recent extension destinations, each for seven days. Collection defaults off.
Recent destinations concern routes inside this extension; no browser history
permission is requested. Credentials, exact private targets, URLs, raw errors,
authored notes and private profile labels do not enter these journals.

## Recent extension destinations

With verified active consent, the center records its first admitted current view
and subsequent accepted destinations. Canceling a guarded departure, choosing
**Keep editing**, refreshing a read or returning focus does not create a visit.
Navigation while the page is hidden or unfocused is not captured later. A
read-only center window can record its own consented destinations; it still
cannot edit preferences or collection controls.

Only the local route and, for a feature page, its registered feature identifier
are retained. Profile labels and profile-detail paths are removed before the
observation leaves the page. This covers the extension's center, not ordinary
GitHub navigation or browsing history.

Capture requires known consent and a known collection generation at the time
of observation. Visits made while collection is off or unknown are not filled
in after enabling it. Losing the native context or clearing the journal retires
old capture state. A missing response never triggers an automatic resend.

The recent-destination panel discloses observations whose delivery could not be
confirmed in this window, separately from retained entries and native writer
state. The sender holds at most one active delivery and one latest waiting
destination. Replacing a waiting observation increases that local uncertainty
count. Neither a confirmed delivery nor a successful primary action proves that
history storage retained an entry. Reading state does not replay missing visits.

## Inspect the last preference operation

**Last preference operation** is available across the local center, expanded in
Activity and Diagnostics. **Read last operation** inspects only the current
window's background metadata. It remains independent of preference reads and
optional history: collection can be off or history storage unavailable. Reading
does not confirm, cancel, retry or start any write, permission request or GitHub
request.

The panel distinguishes a reviewed change, pending confirmation, an observed
write attempt, cancellation, a preflight block, verified saving and an unknown
result. It shows the last proved acknowledgement and observed persistence
separately. A failed later inspection preserves those proved facts while
retiring the private target. **Read current settings** can reconcile an uncertain
save against its exact retained receipt and complete expected settings, without
repeating the write. Reading last-operation metadata alone does not read settings
or establish that reconciliation.

A captured profile label or repository target belongs only to this current
operation. It is never added to generated history or its JSON export. The native
owner keeps one current entry per window, at most eight, for five minutes from
first observation. Reads do not extend that period. Losing the current source,
expiry, replacement or background shutdown removes the target; it cannot be
rebuilt from saved preferences or history. Leaving focus hides current target
detail until a new source-checked inspection. A cleared or unavailable current
entry is not evidence that a submitted write did nothing.

History retention is a separate result. A successful save does not prove a
retained row. Preference previews observed with collection off or unknown are
never added retrospectively after activation. A previously admitted operation
may update its exact existing row while collection is off, until a clear or
other generation change invalidates its ticket. This first implementation covers
preference operations; connection and compound collection results require their
own separate phase facts.

## Review enable or stop

1. In the current editor window, choose **Review enable** or **Review stop**.
2. Inspect the before/after preference and durable policy for this collection
   in the current browser profile.
3. Confirm that exact review, or cancel before effects.
4. Inspect the independent preference and collection step results.

Enabling saves the opt-in before activation. Stopping attempts the durable pause
before saving the off preference. One successful step does not establish that
both completed. Importing or restoring an enabled preference does not activate
capture. A global pause can retain saved consent while pausing actual admission.

An acknowledged request and a canonical completion are separate facts. If the
response is lost, **Check this result** reads the retained owner's result without
repeating the effect. A failed check cannot erase an already observed completed
fact or a known acknowledgement. An owner reporting no observed submission does
not prove that an earlier request cannot still arrive. No automatic write retry
is made. A submitted operation keeps navigation guarded while its request is
pending; closing the UI cannot undo a native transaction.

Operation history, when available, labels intent, acknowledgement and observed
result separately. **First observed** is the timestamp of the initial retained
observation, not a fabricated completion time. A helper reason describes its
recorded observation; it does not certify that the helper is blocked now.
Incomplete history is disclosed and does not change the primary action's result.

## Clear generated entries

Stop collection first. **Review clear** binds the exact collection, generation
and revision, and shows the retained entry count. Confirming that review removes
only those generated entries. It preserves the small generation, revision and
clock controls that reject old writes after clear. These controls and consent
receipts persist until native extension-data removal.

Preferences, protected credentials, authored notes, the temporary current-operation
view and GitHub content are outside this clear. Use their separate controls.
Stopping alone preserves existing
history until expiry or a separately reviewed clear. An unknown clear response
is not presented as a successful deletion; inspect its retained result and the
current state separately.

## Review a JSON download

Choose **Review JSON export** for available retained entries. The read-only JSON
field contains the exact nonsecret bytes proposed for download. A separate
**Download reviewed JSON** gesture creates a local file with a fixed name.
Canceling the export makes no download. Changing or invalidating the read
observation retires the displayed export; read state and review again.

The generated-history JSON is bounded to64KiB. It includes only the selected
closed history snapshot, never preferences, policy nonces, credentials or private
native selectors. A failed native download keeps the review and reports the
failure. It does not claim that the browser saved a file. Preference exports and
imports remain separate under **Data and recovery**.
