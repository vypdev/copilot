# Bugbot failure scenarios

<AccordionGroup>
  <Accordion title="Agent or model policy fails" icon="microchip">
    Stop before workspace mutation. Verify the selected runtime, qualified model, and allowlists.
  </Accordion>
  <Accordion title="Credential or permission is missing" icon="shield">
    Stop and correct the workflow secret reference or GitHub permission. Never print or copy the secret into arguments.
  </Accordion>
  <Accordion title="The agent response is invalid" icon="circle-exclamation">
    Treat malformed JSON or unparseable output as terminal after the bounded partition-local recovery attempt. For a partitioned PR review, every response must echo the exact partition id and canonical head SHA. Each query's structured-output schema permits only its trusted assignment values, so examples inside the diff cannot redefine them; Bugbot still checks the returned values exactly. Bugbot retries an agent-call failure or unusable locale/attestation response for that partition up to two additional times with the same prompt, schema, and head, inside its existing concurrency slot. An unusable response remaining after that bound, or any non-owner resolution claim, invalidates the whole aggregate; Bugbot publishes no partition-local finding, resolves no prior finding, and leaves the existing status card unchanged. Retry the current head after inspecting the failed reviewer step and its content-free failed-partition telemetry. A legacy empty single-query result may still reconcile the canonical status card when a PR target is known and writable.
  </Accordion>
  <Accordion title="The diff exceeds the exhaustive review ceiling" icon="layer-group">
    Bugbot permits exactly 64 bounded partitions, but a 65th is rejected, plus at most 2,000 aggregate candidate findings for one canonical SHA. Malformed provider change metadata (including invalid path, status, or line counts) and patches containing isolated UTF-16 surrogates are rejected before ignore filtering or review; Bugbot never presents invalid metadata or a lossy fragment as complete. It stops before model execution when the plan itself is too large or malformed, or before publication when aggregate output exceeds its cap. No partial finding or resolution is published. Split an oversized pull request into coherent reviewable changes, or correct the malformed diff source, then rerun.
  </Accordion>
  <Accordion title="Every changed file is ignored" icon="circle-question">
    This is an explicit zero-work result, not a hidden legacy review. For a canonical pull request, Bugbot reports the ignored-file count, makes no reviewer request, publishes no new finding, and resolves no existing finding. Previously open findings stay open until a later review includes eligible evidence for them. Change `ai-ignore-files` only when those files should be reviewed, then run `/copilot recheck`.
  </Accordion>
  <Accordion title="Verification fails" icon="check-circle">
    Keep the workspace changes isolated, report the failed command, and do not commit or push.
  </Accordion>
  <Accordion title="The review and its thread disagree" icon="rotate">
    Bugbot reports `verification-required`, never clean. A retry completes bot-owned partial transitions. If a person reopened a resolved thread, run `/copilot recheck` so the agent explicitly verifies whether the finding is active, fixed, or obsolete. This also supports a withdrawn dismissal: the original marker's reason can be refreshed after the native thread is revalidated. Existing finding text, earlier notes, comments and reviews remain audit history; the latest resolution note and canonical status describe the verified current result.

    If the reviewer omits the retained finding or current native facts cannot be read, it stays non-clean. Inspect the exact thread, make its evidence available and recheck after correcting the reported provider failure. Do not delete the review, edit a bot marker, or loosen `allowHumanDismissed` to clear it. A dismissal renewed while analysis runs is preserved. If the marker update succeeded but resolving the native thread failed, the next fresh recheck completes that transition without duplicating the review.
  </Accordion>
  <Accordion title="A historical review still looks stale" icon="clock">
    Use the canonical **Bugbot status** card and `Copilot / Review` Check for the aggregate state. Run `/copilot recheck` to repair the generated status block; the historical snapshot text is intentionally retained.
  </Accordion>
  <Accordion title="A finding changed title or appears twice" icon="rotate">
    A uniquely matched finding keeps its original finding ID and native thread
    link, even when its current title or location changes. Upgrade the Action
    and run one `/copilot recheck` on the current PR head to refresh this evidence.
    Unknown rows include their exact finding IDs for investigation. If two
    retained records could match, inspect both threads and compare the causal
    defect and required fix. Keep an ambiguous record unresolved; use the
    documented evidence-based dismissal only for a verified duplicate or false
    positive. Never resolve an unknown merely because a later scan omits it.

    A candidate whose publication failed has no durable native finding marker.
    Its unknown row describes that failed attempt; a later scan can produce a
    different candidate set. Disappearance from the later aggregate does not
    prove a fix or a dismissal. Preserve the failed run's finding IDs and inspect
    those concerns against the exact head before relying on the later review.
  </Accordion>
  <Accordion title="The status card says partial or unknown" icon="triangle-exclamation">
    Do not treat the review as complete. Open **Incomplete coverage**, review every named source, and manually inspect omitted items. Prompt-sized PR diffs are partitioned exhaustively, so `diff` partial now indicates a provider enumeration limit rather than the old single-prompt packing omission. Split a PR that exceeds the provider scope; for comment/history/rule caps, reduce the relevant scope when practical or restore provider access before rerunning. The context limits are fixed safety boundaries, not configuration knobs. Retained evidence may produce findings, but Bugbot cannot declare the whole PR clean or resolve omitted history. Even with zero observed findings, the Review Check remains neutral, `state:ready` is removed, and lifecycle becomes `state:blocked` plus `state:awaiting-maintainer`. Repeating `/copilot recheck` against the same capped provider evidence cannot improve coverage. A provider or permission error is `unavailable` and aborts before analysis; correct access or wait for the rate limit before retrying. Every final-read surface is tracked independently, so an empty verified result is not confused with a failed read. A previously observed non-clean finding that disappears remains visible as `unknown`; only fully resolved findings may be omitted safely.
  </Accordion>
  <Accordion title="The Job Summary says finding-state evidence is invalid" icon="triangle-exclamation">
    Bugbot rejects the result instead of treating an omitted aggregate or missing, extra, fractional, negative, non-finite, or overflowing state counts as zero. It also rejects duplicate telemetry or a valid snapshot beside a malformed owned sibling; valid zero counts cannot conceal invalid telemetry. `completed`, `no-findings`, `partial`, and `dry-run` outcomes must include all seven canonical counts. The Action and eligible Review Check fail closed, lifecycle stays blocked, and `/copilot status` does not invent counts. Metadata-only, `skipped`, `superseded`, and `failed` results may omit counts because none can claim a clean analysis. Inspect the producing workflow result, correct the result schema or retry the current released Action, then run `/copilot recheck`.
  </Accordion>
  <Accordion title="Two pull requests match the exact head" icon="code-branch">
    Bugbot reports an ambiguous target and performs no model call or finding mutation. It never guesses by pull-request age, number, or provider order. Close the obsolete PR or run the review from the intended pull-request event so that exact identity can be verified.
  </Accordion>
  <Accordion title="The pull-request event identity is stale" icon="git-commit">
    Bugbot requires a positive event PR number, then verifies the PR's open state, base repository, head owner/ref, and head SHA. A missing, malformed, or mismatched identity stops the run without falling back to a branch search. Start a new review for the current PR revision.
  </Accordion>
  <Accordion title="The PR received a newer commit during reconciliation" icon="git-commit">
    Bugbot checks the PR head immediately before and after collecting the final snapshot. If either head differs from the analyzed commit, it discards the snapshot and performs no review/status writes. The newer workflow run owns the next projection; use `/copilot recheck` only if no newer run is active.
  </Accordion>
  <Accordion title="A manual resolve or reopen is not reflected yet" icon="users">
    Native thread actions do not trigger a supported GitHub Actions event. Run `/copilot recheck` for immediate aggregation, or wait for the next pull-request, push, or explicit review event.
  </Accordion>
  <Accordion title="Historical review cards need repair" icon="layer-group">
    Bugbot updates historical review blocks in sequential batches of 20, up to 100 per run. If more remain, or a batch fails, the status card and Check report the exact unattempted count and the Action uses `workflow.presentation-pending` for a budget remainder. This does not mean the provider is unavailable or that the diff was only partly analyzed. Re-run `/copilot recheck` after inspecting any separate write failure; successful updates are kept and already-current blocks are skipped. The canonical status card remains the aggregate view throughout.
  </Accordion>
  <Accordion title="A native review exists but finding reconciliation failed" icon="triangle-exclamation">
    Successful publication can precede a later failed marker/thread mutation. The recovery details identify the publication or resolution stage, exact operation, affected finding (plus batch count), HTTP status and provider request reference when available. Missing provider metadata is explicitly unavailable. Existing reviews, comments and durable dismissal intent are retained; a zero completed-publication count on a failed run does not prove that no native review exists.

    Correct permanent credential/access or contract failures before retrying. For a transient outage or rate limit, restore provider availability first, then run `/copilot recheck` on the same PR. The normal fresh provider read reconciles existing comments and threads rather than recreating completed effects. Do not delete a review or install an application dependency merely to clear an unrelated finding-publication failure.

    **Incomplete coverage** remains separate. `human-conversation` lists retained, omitted and truncated counts plus `truncated-source-ids` for exact retained records, such as `issue:6311517518` (a general issue/PR comment ID) or `review:PRRC_50` (an inline comment node ID). Complete comments are retained through bounded fragments when the rendered section permits; the 4,000-unit fragment bound alone does not mean truncation. Inspect a genuinely incomplete source from the linked PR/issue, preserve its substantive decisions and reduce only redundant text before rechecking. Malformed Unicode stops a complete result rather than fabricating replacement evidence. Source IDs contain no comment text. A mutation retry never upgrades incomplete conversation evidence to complete.
  </Accordion>
</AccordionGroup>

## A valid self-repository Action reference is reported as invalid

Record the authored `uses` value, containing workflow/action revision, host and
version. Check the applicable official contract and checkout order. GitHub.com
supports `$/path` from the containing repository at the running commit without a
checkout; `./path` needs the files in the workspace. A resolved SHA in a job log
is distinct from a literal source pin and does not invalidate a remote tag policy.
An appended `@ref`, a missing workspace checkout or an unsupported host may still
be a real defect.

Attach matching source and available same-revision execution evidence to normal
finding verification, then run `/copilot recheck` on the current head. Guidance
alone does not dismiss the prior finding or certify an unexecuted workflow.
Do not replace a working bootstrap reference or relax a remote-version policy
solely to satisfy an unsupported claim. See [reference evidence](/bugbot/detection#self-repository-action-references).

## A reported invalid input is already rejected

Preserve the exact string, including invisible Unicode and separators, and inspect
the reviewed source revision. Trace transforms, every rejecting guard, collection
predicates and the actual caller/effect. For example, consecutive dots produce an
empty middle domain label; a universal nonblank predicate rejects that label even
when a different label contains U+200B. A request for a stricter character policy
is a separate product decision, not proof that this value was accepted.

Attach applicable same-revision source and, when available, matching execution
evidence to normal finding verification/re-review. Do not invent an execution,
weaken valid input support or automatically dismiss findings from a prose match.
A real ignored validation result or transform that creates an invalid value after
checking remains actionable. Evidence cannot grant new mutation, approval or
lookup permissions. See [exact validation witnesses](/bugbot/detection#exact-validation-witnesses)
and [quality evidence limits](/bugbot/quality-observability).


## A Kotlin/Wasm parameter is reported as an unbound JavaScript global

Inspect the exact package-level function signature and its target/compiler
version. A declared parameter of `= js(...)` is available in the generated
JavaScript function and can be captured by a nested callback. Attach applicable
[official interop documentation](https://kotlinlang.org/docs/wasm-js-interop.html#kotlin-functions-with-javascript-code)
and, when available, same-source generated imports and executed test results to
normal finding verification/re-review. A green job on another target does not
prove this bridge succeeds. Keep actual missing identifiers actionable; avoid
introducing global state to satisfy a disproved scope claim. Evidence alone does
not auto-dismiss findings or grant permissions. See [parameter scope](/bugbot/detection#kotlinwasm-javascript-parameter-scope).


## A review claims that an existing relative link is broken

Check the source document's directory, the literal link and its normalized
target at the reviewed commit. Inspect the fragment under the actual renderer's
heading or custom-anchor rules. Include those facts when requesting
`/copilot recheck`; a prior confidence score does not prove the path claim.
Keep working links intact. A missing file or fragment remains actionable, while
unavailable source context cannot establish either failure or resolution.
