# Bugbot failure scenarios

<AccordionGroup>
  <Accordion title="Agent or model policy fails" icon="microchip">
    Stop before workspace mutation. Verify the selected runtime, qualified model, and allowlists.
  </Accordion>
  <Accordion title="Credential or permission is missing" icon="shield">
    Stop and correct the workflow secret reference or GitHub permission. Never print or copy the secret into arguments.
  </Accordion>
  <Accordion title="The agent response is invalid" icon="circle-exclamation">
    Treat malformed JSON or unparseable output as terminal. Do not publish an inferred finding. When a PR target is already known and writable, Bugbot preserves prior durable facts and updates the canonical status card with the failed reconciliation.
  </Accordion>
  <Accordion title="Verification fails" icon="check-circle">
    Keep the workspace changes isolated, report the failed command, and do not commit or push.
  </Accordion>
  <Accordion title="The review and its thread disagree" icon="rotate">
    Bugbot reports `verification-required`, never clean. A retry completes bot-owned partial transitions. If a person reopened a resolved thread, run `/copilot recheck` so the agent can decide whether the finding is active or still fixed.
  </Accordion>
  <Accordion title="A historical review still looks stale" icon="clock">
    Use the canonical **Bugbot status** card and `Copilot / Review` Check for the aggregate state. Run `/copilot recheck` to repair the generated status block; the historical snapshot text is intentionally retained.
  </Accordion>
  <Accordion title="The status card says partial or unknown" icon="triangle-exclamation">
    Open **Coverage** and **Technical details**. A fixed context cap is `partial`: retained evidence may produce findings, but Bugbot cannot declare the whole PR clean or resolve omitted history. Inspect the named source, split an oversized PR if appropriate, then run `/copilot recheck`. A provider or permission error is `unavailable` and aborts before analysis; correct access or wait for the rate limit before retrying. Every final-read surface is tracked independently, so an empty verified result is not confused with a failed read. A previously observed non-clean finding that disappears remains visible as `unknown`; only fully resolved findings may be omitted safely.
  </Accordion>
  <Accordion title="Two pull requests match the exact head" icon="code-branch">
    Bugbot reports an ambiguous target and performs no model call or finding mutation. It never guesses by pull-request age, number, or provider order. Close the obsolete PR or run the review from the intended pull-request event so that exact identity can be verified.
  </Accordion>
  <Accordion title="The pull-request event identity is stale" icon="git-commit">
    Bugbot requires a positive event PR number, then verifies the PR's open state, base repository, head owner/ref, and head SHA. A missing, malformed, or mismatched identity stops the run without falling back to a branch search. Start a new review for the current PR revision.
  </Accordion>
  <Accordion title="The PR received a newer commit during reconciliation" icon="git-commit">
    Bugbot checks the PR head immediately before and after collecting the final snapshot. If either head differs from the analyzed commit, it discards the snapshot and performs no review/status writes. The newer workflow run owns the next projection; use `/copilot recheck` only if no newer run is active.
  </Accordion>
  <Accordion title="A manual resolve or reopen is not reflected yet" icon="users">
    Native thread actions do not trigger a supported GitHub Actions event. Run `/copilot recheck` for immediate aggregation, or wait for the next pull-request, push, or explicit review event.
  </Accordion>
  <Accordion title="More than 20 review cards need repair" icon="layer-group">
    Bugbot updates 20 historical review blocks per run and reports the exact remainder. Re-run `/copilot recheck` until the pending count reaches zero; the canonical status card remains the aggregate view throughout.
  </Accordion>
</AccordionGroup>
