# Overview

Copilot connects work across GitHub issues, branches, pull requests, Projects and releases. Its local CLI configures the installation; the GitHub Action responds to the installed repository events and explicitly addressed commands.

## Choose what to automate

| Capability | Typical result | Needs an agent? | Guide |
|---|---|---|---|
| Issue and branch lifecycle | An admitted issue gets a verified working branch after `in-progress` | Branch creation itself does not; planning and required SDDs do | [Issues and branches](/guides/issues-and-branches) |
| Projects and native metadata | Linked items and matching Status, assignee and lifecycle updates | No, for metadata operations | [Issues and branches](/guides/issues-and-branches#add-project-tracking) |
| Bugbot and progress | Current findings, review status and evidence-based progress | Yes | [PR review](/guides/review-pull-requests) |
| Explanations, planning and implementation | A correlated answer or verified commit on the authoritative branch | Yes, for analysis and implementation | [Work with the bot](/guides/work-with-the-bot) |
| Branch synchronization | Drift notices and a verified merge after an authorized command | Detection is agent-free; eligible conflicts may use the fixer | [Branch synchronization](/issues/branch-synchronization) |
| Release and hotfix orchestration | Protected promotion, publication and development reconciliation | Depends on your preparation/build steps | [Releases and hotfixes](/guides/releases-and-hotfixes) |

## Who does what?

- **Installer/operator:** chooses capabilities, scopes, credentials and runners, reviews the setup plan, and installs generated files on the intended branches.
- **Developer:** opens an Issue Form, contributes on the verified linked branch, opens a PR, and responds to checks and findings.
- **Authorized maintainer:** starts admitted work, authorizes file-changing bot requests, reviews and merges through branch protection, and explicitly launches releases.
- **Copilot Action:** owns managed branch creation, naming, synchronization and cleanup. It performs configured automation using the workflow bot identity.

Generated repository guidance records the installed contract in `.copilot/repository-profile.json` and `.copilot/AGENT_GUIDE.md`. Collaborator agents follow that contract and contribute ordinary commits on the existing Action-managed branch.

## Installation has two verification steps

1. [Web setup](/setup-web) prepares local files and selected GitHub resources. Its read-only verification checks installation metadata; it cannot prove a Secret's value or a real agent run.
2. [First workflow](/first-workflow) exercises the installed events using one documentation issue and linked PR. It shows the GitHub results that establish a working path.

You can then enable additional [goals](/guides). Release templates provide the orchestration and extension points; your product's build and deployment remain repository-specific.

## Agent execution contract

AI tasks use one runtime CLI and one qualified model per run:

```text
agent-provider        = runtime CLI
agent-model-provider  = model provider
agent-model           = model name
agent-effort          = optional reasoning effort or model variant
qualified model       = agent-model-provider/agent-model
```

The default is `codex` with `openai/gpt-6-luna`. Copilot validates runtime, model policy and credentials before execution. See [Agents](/agents) for configuration, [Authentication](/authentication) for the two PAT roles, and [Security & Operations](/security-operations) for runner and credential boundaries.
