# Configuration checklist

## Action contract

- [ ] `token` is supplied as a repository or organization secret.
- [ ] `agent-provider`, `agent-model-provider`, and `agent-model` are explicit.
- [ ] `agent-effort` is set when the selected model/provider supports a specific effort or variant.
- [ ] `AGENT_ALLOWED_MODEL_PROVIDERS` contains the selected model provider.
- [ ] `AGENT_ALLOWED_MODELS` contains the exact qualified model.
- [ ] `agent-executable` is omitted unless an exact basename or absolute executable path is required.
- [ ] Secrets and Variables have been chosen independently as repository- or organization-scoped resources.
- [ ] Organization-scoped resources use an intentional visibility (`selected`, `private`, or `all`) and the setup PAT has organization Actions permissions.
- [ ] Existing organization resources are inherited deliberately; named repository overrides are listed when needed.

## Credentials

- [ ] Credentials are configured as secrets or as a local self-hosted credential store.
- [ ] No session file or token is copied into GitHub Secrets.
- [ ] Secret values are never placed in `.copilot-setup.yml`, command configuration, or Variables.
- [ ] Fork workflows cannot access write credentials.
- [ ] `pull_request_target` does not execute attacker-controlled checkout content.

## Operations

- [ ] The selected CLI is preinstalled and verified, or its Copilot-owned installation package is pinned.
- [ ] Node.js 24 is set up before any workflow step that may install a pinned Codex or OpenCode package.
- [ ] Cursor is preinstalled when selected; no automatic Cursor installer is configured.
- [ ] Provisioning and help checks pass.
- [ ] Smoke tests are recorded without printing credentials.
- [ ] Rollback refs and previous CLI versions are known.

## Setup and diagnosis

- [ ] Unattended setup uses `--non-interactive --yes` plus every required external credential; `--yes` is treated only as plan approval.
- [ ] Cancellation (`Ctrl-C` or EOF) has been observed to exit 130 with no writes; declining the final plan exits 0 with no writes.
- [ ] Setup review lists Secret names only and no secret value appears in config, plan, logs, errors, reports, fixtures, or backups.
- [ ] `copilot doctor` reports stable check IDs with `pass`, `warn`, `fail`, or dependency-blocked `skipped` and exits non-zero only for `fail`.
- [ ] Invalid setup-PAT diagnosis still returns independent local checks; remote dependants identify their blocking check.
- [ ] Doctor is wired only to query ports. Temporary credential-health workflow bootstrap remains setup-only.
- [ ] No legacy setup prompt adapter, compatibility result, dual reader/writer, state alias, or transitional flag is present.

## Release and hotfix orchestration

- [ ] `copilot_deployment_orchestration.yml` and every enabled publishing workflow (`release_workflow.yml` and/or `hotfix_workflow.yml`) are committed on the repository's default branch before an operation starts; this project enables both.
- [ ] The workflow PAT can write Contents, Issues, Pull requests, and Actions; can read Metadata and classic branch-protection Administration policy; and belongs to a bot identity different from the release operator.
- [ ] Merge commits are allowed when `production-lineage` is selected.
- [ ] Native auto-merge is enabled when explicitly selecting `auto-merge`.
- [ ] Every required GitHub Actions check has an exact static job name and `merge_group: checks_requested`; third-party integrations report on `gh-readonly-queue/<base>` branches.
- [ ] Every otherwise-unknown third-party or ambiguous check has a reviewed exact attestation matching its context, integration ID (or explicit `any` source), and logical target; no attestation is used to override known contrary evidence.
- [ ] `copilot doctor --config <setup.yml>` reports production and development queue readiness after workflows and Variables are on the default branch; active release branches are revalidated dynamically during hotfix reconciliation.
- [ ] The 12 orchestration Repository Variables are reviewed, including `MERGE_QUEUE_CHECK_ATTESTATIONS` (recommended default `[]`).
- [ ] For this project's package publication, the exact GitHub Environment `npm` exists and npm Trusted Publishers name `vypdev/copilot`, that Environment, and both publishing workflow filenames exactly.
- [ ] Each npm publisher allows direct `npm publish`; no `NPM_TOKEN` or `NODE_AUTH_TOKEN` is configured for the OIDC path.
- [ ] Node/npm meet npm Trusted Publishing minimums, `package.json.repository.url` matches the publishing repository, and the visibility interval/timeout are within their documented bounds.
- [ ] A real end-to-end run has verified the issue control center and PR copy in GitHub; source-level tests cannot replace this manual UX gate.

See [Release and hotfix orchestration](/issues/deployment-orchestration) for the
exact values, defaults, decision paths, and recovery procedure.
