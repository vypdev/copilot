# Local setup assistant acceptance review

The [350-case acceptance ledger](../../specs/local-web-setup-assistant-acceptance.json)
is the source of truth for case status. Automated tests establish structural
and behavioral facts. The 40 manual-review rows require a named reviewer, provenance, environment
and direct observation for each pass. Do not infer a visual,
linguistic, assistive-technology, or operating-system pass from Jest, SSR HTML,
or a screenshot alone.

## Safe fixture setup

1. Build the package with `pnpm run build` in a disposable checkout. Do not
   run `copilot setup` against this or any other real repository for review.
2. Run `node scripts/serve-web-setup-review.cjs pending`. The script serves
   the compiled browser UI and canned redacted views on `127.0.0.1`. It has
   no GitHub, filesystem mutation, PAT, Issue, or Action adapter. Open the
   printed local URL and enter the printed **fixture** pairing code.
3. Repeat with `action-required`, `blocked`, `partial`, `completed`,
   `cancelled`, and `expired`. Stop the previous fixture before switching.
   The fixture rejects answer and close commands; use it to review visible
   content, navigation, focus and contrast, not to claim a successful setup.
4. Keep the browser console and network panel available. Record any missing
   static asset or unintended external request. The GitHub PAT settings link
   is informational; do not follow it to create a token for this review.

For setup layout regressions, the same fixture supports `plan`, `checks`,
`question`, `credential`, and `blocked-permissions`. `plan` has 29 files, 15
workflows and 68 Variables: open each inventory and verify that every item
appears in page flow, with no internal scrolling. Check that warnings remain
visible, decision rows align, and the page has consistent spacing. `checks`
shows 12 selectable CI cards without a fixed-height scroller. `question` has no
Previous button; Continue must remain on the right. `credential` uses the same
navigation row. `blocked-permissions` explains the Workflows prerequisite for
Actions separately from the independently denied Workflows grant. Review each
at desktop and narrow widths in both themes; these fixtures contain no PAT and
reject all setup commands.

The `blocked-permissions` fixture also retains the corrected guided PAT link
after the result replaces transient messages. Verify that the additional
Workflows grant, repository selection and fresh-run instructions are visible
in English, Spanish, French and Portuguese, with consistent spacing and no
internal scroller. Inspect the link target without following it: it must point
to GitHub's PAT creation form with `workflows=write`. The fixture cannot prove
that a real token has that grant or that a live Actions dispatch succeeds.

leave it open when a platform, assistive technology or language reviewer is
unavailable. Run `pnpm run validate:setup-acceptance` after editing it.

## Interactive journey fixture

After building, run `node scripts/serve-web-setup-journey.cjs`. Pair using its
printed code. Both masked credential fields accept only the literal
`fixture-value`; never enter a real credential. The fixture uses the production
bridge, loopback transport, compiled UI and question explanations, with scripted
prompts and no GitHub or filesystem mutation adapters. Its six-stage journey
ends in a preview with skipped resources. Inspect the official PAT-settings
link without following it, then close the session. Restart the fixture to
repeat a locale, viewport or theme; restart it after rebuilding assets.

Use Tab, Shift+Tab, Space and Enter to inspect focus order, recovery from an
incorrect pairing code, field labels, expanded plan inventories and the final
receipt. Keep a narrow or tablet width fixed through an entire replay, rather
than relying only on resizing an already completed desktop journey. A server
close must preserve the rendered result, remove controller actions and change
the active session indicator. A rejected close must display recovery guidance
without replacing the receipt or claiming the server stopped.

The progress rail shows only the completed facts supplied by setup. Its current
position does not independently prove completion of earlier stages. Unknown
causes also do not erase known completed-resource receipts. Long repository
names wrap completely in the header so the target remains inspectable in a
narrow result view.
