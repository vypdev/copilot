# Testing

Use Corepack and the pinned pnpm toolchain:

```bash
corepack pnpm@10.12.4 run typecheck
corepack pnpm@10.12.4 run lint
corepack pnpm@10.12.4 run test:coverage
corepack pnpm@10.12.4 run eval:bugbot
corepack pnpm@10.12.4 run build
corepack pnpm@10.12.4 run validate:agent-docs
corepack pnpm@10.12.4 run validate:docs-page
corepack pnpm@10.12.4 run validate:documentation
corepack pnpm@10.12.4 run validate:workflows
corepack pnpm@10.12.4 run validate:specifications
git diff --check
```

`validate:documentation` also enforces heading fragments, the complete setup
workflow and single-action catalogs, parity between the six embedded issue
examples and their setup templates, and high-risk release contracts such as
the default-branch continuation prerequisite, npm direct-publish policy,
polling controls, and orchestration Variables. It also rejects removed public
inputs, actions, commands, and orchestration modes.

`validate:specifications` validates unique capability ownership, safe existing
repository-relative evidence paths, complete registration of top-level SDDs,
retrospective-baseline structure, and byte-for-byte freshness of the generated
`specs/CATALOG.md` view.

Merge-queue contract tests cover ruleset-only targets, classic/ruleset union,
GitHub Actions workflow parsing on target and candidate refs, external exact
attestations, setup/doctor drift, pre-PR and pre-enqueue ordering, queue
membership idempotency, and head-bound enqueue. These tests use provider fakes;
they never create a live queue entry or poll check runs.

These deterministic checks cannot inspect live GitHub/npm settings or judge
desktop/mobile, light/dark, and assistive-technology rendering; keep those as
explicit operator and human UX gates.

Tests MUST isolate environment variables such as `AGENT_PROVIDER`, `AGENT_MODEL_PROVIDER`, `AGENT_MODEL`, and `AGENT_EXECUTABLE`. Real provider smoke tests are separate from deterministic unit tests and MUST NOT run without authorization and cost controls. Coverage thresholds are enforced by Jest and must not be reduced to accommodate a new code path; add focused tests instead.

`eval:bugbot` runs the offline Bugbot quality harness. Corpus cases score precision, recall, F1, exact-location, severity, category, line distance, false positives/negatives, and confidence calibration independently, so prompt or model changes cannot hide false positives behind a single pass/fail number. `copilot bugbot-benchmark` can generate predictions with the real configured agent for a cost-controlled manual or scheduled gate; `copilot bugbot-eval` scores them. Ground truth is not passed to the agent. Extend the corpus when a production review exposes a new failure mode.

`copilot bugbot-analytics` aggregates content-free telemetry exported by the Action. Do not add prompt, diff, source, comment, response, credential, or rule content to the telemetry schema.

Workflow queue tests inject a clock, random source, and scheduler/delay port. They
cover workflow-scoped active-status traversals and later-page matches, strict
lower-ID/workflow-file filtering, malformed responses, fail-closed provider errors, 429 and
rate-limited 403 headers, bounded fallback backoff/jitter, and the absolute deadline.
The workflow contract test keeps the nine queue-bearing workflow names synchronized with the
validator and verifies the `90m queue / 120m job` budget, required runners, action
inputs, missing/short timeouts, forbidden durable-mutation concurrency, and the
exact shared branch concurrency contract permitted only for Commit/Pull Request
Bugbot jobs.

GitHub lifecycle tests cover admission before queue polling, PAT-owner normal-run
discard, valid single-action preservation, identity lookup failure, and the absence
of project composition, agent provisioning, setup, publication, and persistence on
discarded runs.

The lifecycle replay integration suite feeds normalized, serialized-shaped
`pull_request_review` payloads through the real lifecycle synchronization use
case. It verifies deterministic labels for approved reviews, requested changes,
and ambiguous multi-PR events without invoking an agent route. External check
workflows are intentionally outside the workflows shipped by Copilot.

Configuration tests cover current-schema round trips and fail-closed handling of
missing, malformed, or different-version durable values. Architecture tests also
guard the narrow context contracts used by extracted policies and lifecycle
reconciliation.

Branch synchronization tests cover durable configuration and linked-branch discovery,
pagination, parent/child comparisons, bot-owned sticky comments, explicit and natural-language
commands, authorization, dry runs, clean merges, conflict eligibility, agent postflight,
credential-free verification, unexpected workspace mutations, and remote-head races. The
all-branch observer workflow is also contract-checked to remain free of agent inputs.

Architecture tests additionally verify that production imports remain acyclic,
application code does not depend on concrete adapters, and pure model/policy
code remains free of runtime, provider, and logging dependencies. Refresh the
local topology before an architecture review with Graphify, and use the
RepoWise index-only health/dead-code reports to distinguish current complexity
from history-based churn signals:

```bash
graphify update .
repowise init . --no-workspace --no-prose --no-agents --no-editor-setup \
  --coverage-report coverage/lcov.info
repowise dead-code --safe-only --format json --no-workspace
```

Security regression tests must cover untrusted prompt fields, control-sequence
neutralization, schema rejection, local finding fingerprints, stale finding
resolution, provider credential isolation, and the language capability's
separate application port. A passing model smoke test does not replace these
deterministic tests.

Setup tests also cover the setup/workflow PAT separation, provider validation,
per-credential remote health results, invalid-secret replacement, workflow update
approval and backups, `.env` exclusion, and the read-only doctor path.

The reproducible `metrics:architecture` collector is the full evidence
workflow; it requires a clean working tree and writes reports outside the
repository.
