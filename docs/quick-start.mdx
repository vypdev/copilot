# Quick start

## Recommended setup

The supported onboarding path is the global CLI package followed by
`copilot setup`. It initializes the repository and lets you select the workflows,
templates, labels, issue types, Variables, Secrets, and agent settings together.

```bash
pnpm add --global @vypdev/copilot
copilot --version
cd /path/to/your/repository
copilot setup
```

Use `copilot setup --dry-run` to review the plan without changing files or GitHub.
The setup PAT used by the operator is separate from the workflow `PAT` Secret.
After setup, review and commit the generated `.github/` files, then customize the
selected workflows as needed. See [How to use](/how-to-use) for the full flow.

## Manual workflow integration (advanced)

If the setup wizard cannot be used, the Action can be wired directly into a
workflow. This only configures execution; it does not initialize repository
metadata or install the complete Copilot workflow set.

```yaml
name: Copilot
on: push
jobs:
  copilot:
    runs-on: ubuntu-latest
    permissions:
      contents: write
      issues: write
      pull-requests: write
    steps:
      - uses: actions/checkout@fbc6f3992d24b796d5a048ff273f7fcc4a7b6c09 # v5
        with:
          persist-credentials: false
      - uses: vypdev/copilot@a39616557f384bcc633b94e43d9551b2b5205328 # v3
        with:
          token: ${{ secrets.COPILOT_TOKEN }}
          agent-provider: codex
          agent-model-provider: openai
          agent-model: gpt-5.6-luna
          agent-effort: medium
        env:
          # Omit when Codex is already authenticated on the controlled runner.
          CODEX_API_KEY: ${{ secrets.CODEX_API_KEY }}
```

Configure labels, issue types, Variables, Secrets, templates, permissions, and
additional workflows manually when following this path. The example pins the
action to an immutable commit and retains the readable major version in its
comment. Update that pin deliberately after validating a new release.

## Verify before enabling writes

1. Run the workflow with read-only permissions.
2. Confirm the selected agent CLI version and model allowlists.
3. Run the provider smoke procedure.
4. Grant write permissions only to the workflows that need commits or comments.

See [Configuration checklist](/configuration-checklist) and [Security](/security-operations/security/credentials).
