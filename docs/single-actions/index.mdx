# Single Actions

When you set the **`single-action`** input (and any required targets such as `single-action-issue` or `single-action-version`), Copilot runs **only** that action and skips the normal issue, pull request, and push pipelines. Supported on-demand uses include progress checks, Bugbot detection, recommendations, analysis, GitHub Release creation, initial setup, and scheduled inactivity cleanup. Tagging and deployment state transitions are workflow-owned steps bound to a durable release or hotfix operation.

## Quick summary

| Action type | Typical use |
|-------------|-------------|
| **Progress / Bugbot / Recommend steps** | Run on demand with `single-action-issue`; no need to push or wait for the commit workflow. |
| **Think** | Deep code analysis or questions; no issue required. Use from workflow or CLI with `-q "<question>"`. |
| **GitHub Release / Setup** | Create a standalone GitHub Release, or run initial setup for labels and issue types. |
| **Durable deployment callbacks** | Supplied release/hotfix workflows create the accepted tag and advance operation state with the exact issue and operation ID. |
| **Inactive issue cleanup** | Close stale issues waiting for a maintainer or issue author; no issue number required. |

<Info>
**Actions that fail the job** if the last step fails: `publish_github_action`, `create_release`, `close_inactive_issues_action`, `publish_issue_comment`, and all five workflow-owned deployment actions: `create_tag`, `prepare_deployment_action`, `continue_deployment_action`, `published_deployment_action`, and `failed_deployment_action`. The workflow will be marked as failed so you can act on it.
</Info>
