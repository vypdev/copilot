# Agent CLI runners

Copilot uses one provider-specific, headless CLI per run. The provider adapter selects the documented prompt transport: Codex receives the prompt through standard input, while OpenCode and Cursor receive it as one positional argument. The response is read from standard output.

| Runtime | Headless command | Credential reference |
| --- | --- | --- |
| OpenCode | `opencode run --pure --agent managed-role --format json --model provider/model [--variant effort]` | Provider credential, for example `OPENAI_API_KEY` |
| Codex | `codex exec --strict-config --ignore-user-config --ignore-rules --ephemeral --sandbox mode --model model ... -` | `OPENAI_API_KEY`, `CODEX_API_KEY`, or a controlled local ChatGPT session |
| Cursor | `agent -p --output-format text --sandbox enabled --model model [--mode ask\|--force] <prompt>` | `CURSOR_API_KEY` |

There is no user-configurable argument or transport setting, managed server
lifecycle, SDK, or provider fallback. Provider policies reconstruct every argv
token: Codex ends in `-` and receives the prompt through stdin; OpenCode and
Cursor receive one final positional prompt. Invalid selections fail before the
process starts.

At the process boundary, Copilot removes known credentials that do not belong to the selected runtime. Cursor receives `CURSOR_API_KEY` only when Cursor is the selected runtime; the enterprise credential is not used by the default Codex/OpenCode path. A local ChatGPT Codex session also takes precedence over exported Codex credentials. Repository verify commands run with a separate allowlisted environment and temporary `HOME`, without GitHub, agent, cloud, or auth-store credentials.

Every JSON-backed capability is parsed as exactly one object and validated locally against its schema. For schemas compatible with Codex strict Structured Outputs, Copilot additionally creates a private temporary schema file and injects `--output-schema`; caller-provided schema paths are rejected. The file is removed when the invocation settles.

## Configure the runtime and model separately

```yaml
with:
  agent-provider: codex
  agent-model-provider: openai
  agent-model: gpt-5.6-luna
  agent-effort: high
```

For OpenCode, Copilot validates and passes `openai/gpt-5.6-luna` explicitly. Repository-local OpenCode configuration and implicit defaults cannot replace that selection.

## Provisioning contract

The runner must provide the selected executable and credential reference before
the Action invokes it. An available executable is operator-owned: Copilot
records its non-empty version identity and does not replace it. When a default
Codex or OpenCode executable is missing, Copilot installs the exact manifest
package and verifies that installation against the reviewed identity. Cursor
must be preinstalled because it has no reviewed automatic installer.

Required checks:

1. install or reuse only the selected runtime;
2. record a non-empty runtime identity and exactly verify Copilot-owned installations;
3. verify the headless help command;
4. verify the credential reference without printing its value;
5. run a harmless, non-production smoke test when authorized;
6. fail before Copilot starts when a prerequisite is missing (except Codex authentication, which may be resolved by a preinitialized local CLI session).

Do not put secrets in action inputs, YAML literals, command arguments, prompts, or logs. Do not copy local OAuth files into GitHub-hosted CI.

## Verification command

From the repository root:

```bash
node scripts/verify-agent-clis.cjs
```

The verifier reports executable availability, headless help status, and sanitized credential state. A successful help check is not proof that a provider/model request is authenticated; use an authorized smoke test for that.

## Provider notes

### OpenCode

Use an explicit qualified model. For the recommended policy:

```bash
opencode run --pure --model openai/gpt-5.6-luna 'Reply with exactly READY.'
```

### Codex

Codex can use an API credential or a local ChatGPT session. A local session is appropriate only on a self-hosted machine controlled by the account owner; do not export its `auth.json` to GitHub-hosted runners.

### Cursor

The CLI and headless invocation are supported, but a real smoke test requires an authorized `CURSOR_API_KEY`. Cursor validation is intentionally separate from the OpenCode and Codex validation path.
