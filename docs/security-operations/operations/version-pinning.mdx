# Version pinning

Every runtime must have a deliberate ownership and installation policy. A
missing executable is not an invitation to install the latest package implicitly.

| Runtime | Reviewed baseline | Installation boundary | Verification |
| --- | --- | --- | --- |
| Codex | `codex-cli 0.153.4` | Runner `npm` global install | Exact after Copilot install; otherwise identity + smoke |
| OpenCode | `1.18.3` | Runner `npm` global install | Exact after Copilot install; otherwise identity + smoke |
| Cursor | `2026.09.10-fd3934a` | Controlled runner image | Non-empty runtime identity and safe smoke |

The Copilot CLI is distributed as `@vypdev/copilot` and exposes the `copilot` executable. Pin it for reproducible local tooling:

```bash
VERSION=<known-good-version>
npm install --global "@vypdev/copilot@${VERSION}"
copilot --version
```

## Rules

1. Pin every Copilot-owned package installation in the reviewed source-controlled runtime manifest.
2. Provision only the selected runtime.
3. Verify a Copilot-installed package exactly before invoking the agent.
4. Reuse an available operator-owned runtime without silently replacing or downgrading it.
5. For Cursor, require a preinstalled compatible build; automatic installation is unsupported.
6. Treat missing or empty runtime identity and post-install mismatches as terminal failures.
7. Record the effective version and manifest revision in sanitized logs without credentials.

See [Provisioning](/security-operations/operations/provisioning) and [Upgrade and rollback](/security-operations/operations/upgrade-rollback) for the lifecycle procedure.
