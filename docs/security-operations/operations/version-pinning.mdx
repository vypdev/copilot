# Version pinning

Every runtime must have a deliberate version policy. A missing version is not an invitation to install the latest package implicitly.

| Runtime | Accepted version | Installation boundary | Verification |
| --- | --- | --- | --- |
| Codex | `codex-cli 0.153.4` | Runner `npm` global install | Exact CLI version output |
| OpenCode | `1.18.3` | Runner `npm` global install | Exact CLI version output |
| Cursor | `2026.09.10-fd3934a` | Controlled runner image | Exact CLI version output |

The Copilot CLI is distributed as `@vypdev/copilot` and exposes the `copilot` executable. Pin it for reproducible local tooling:

```bash
VERSION=<known-good-version>
npm install --global "@vypdev/copilot@${VERSION}"
copilot --version
```

## Rules

1. Pin the version in the reviewed source-controlled runtime manifest.
2. Provision only the selected runtime.
3. Verify the installed version before invoking the agent.
4. For Cursor, require the exact preinstalled build; automatic installation is unsupported.
5. Treat missing, malformed, or mismatched values as terminal failures.
6. Record the effective version and manifest revision in sanitized logs without credentials.

See [Provisioning](/security-operations/operations/provisioning) and [Upgrade and rollback](/security-operations/operations/upgrade-rollback) for the lifecycle procedure.
