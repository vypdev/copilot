# Agent CLI provisioning

The Action executes external provider-specific CLIs. It does not embed agent SDKs, start an HTTP server, copy authentication files, or fall back to another provider.

## Supported runtimes

| Runtime | Binary | Invocation | Credential reference |
| --- | --- | --- | --- |
| OpenCode | `opencode` | `opencode run --pure --agent managed-role --format json --model provider/model [--variant effort]` | Provider credential, for example `OPENAI_API_KEY` |
| Codex | `codex` | `codex exec --strict-config --ignore-user-config --ignore-rules --ephemeral --sandbox mode --model model ... -` | `OPENAI_API_KEY`, `CODEX_API_KEY`, or controlled local session |
| Cursor | `agent` | `agent -p --output-format text --sandbox enabled --model model [--mode ask\|--force] <prompt>` | `CURSOR_API_KEY` |

## Manifest-owned versions

The immutable manifest owns every accepted version:

```text
Codex CLI: codex-cli 0.153.4
OpenCode: 1.18.3
Cursor Agent: 2026.09.10-fd3934a
AGENT_PROVISIONING=auto
```

The selected provider is provisioned only when needed. Set `always` to reinstall
Codex/OpenCode at the manifest version or `disabled` to require the runner image.
Local and prebuilt runners are accepted only when `--version` exactly matches.
Repository Variables cannot replace, widen, or float the manifest version.

## Approved installation methods

Codex and OpenCode are installed with the pinned package versions using the runner's system `npm`. This avoids depending on a Corepack/pnpm binary on the runner (including the Intel macOS SEA failure mode):

```bash
npm install --global "@openai/codex@0.153.4"
npm install --global "opencode-ai@1.18.3"
```

Cursor automatic installation is unsupported because the public installer does
not select an immutable historical build. Bake the exact manifest version into a
controlled runner image; do not substitute an unofficial npm package.

Do not use `npx`, Yarn, Bun, floating `@latest`, unverified shell downloads, or secrets in command-line arguments.

## Copilot action step environment

```yaml
env:
  AGENT_PROVISIONING: ${{ vars.AGENT_PROVISIONING || 'auto' }}
  OPENCODE_API_KEY: ${{ secrets.OPENCODE_API_KEY }}
  OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
  CODEX_API_KEY: ${{ secrets.CODEX_API_KEY }}
  CURSOR_API_KEY: ${{ secrets.CURSOR_API_KEY }}
```

Map these values only on the Copilot action step, never at workflow or job scope. The Action does not require every secret. Only the credential for the selected runtime/model provider should be supplied, and Codex needs none of these environment values when a controlled runner already passes `codex login status`. Never expose a local OpenCode or Codex OAuth file to a GitHub-hosted runner.

## Recommended model policy

```yaml
with:
  agent-provider: codex
  agent-model-provider: openai
  agent-model: gpt-5.6-luna
env:
  AGENT_ALLOWED_MODEL_PROVIDERS: openai
  AGENT_ALLOWED_MODELS: openai/gpt-5.6-luna
```

The managed Codex shape includes:

```text
codex exec --strict-config --ignore-user-config --ignore-rules --ephemeral --sandbox read-only --model gpt-5.6-luna --config 'model_provider="openai"' -
```

The allowlists are authorization policy, not credentials and not model selectors. A rejected provider/model is a terminal failure.

## Verification

From the repository root:

```bash
node scripts/verify-agent-clis.cjs
```

The verifier never prints secret values. It checks executable availability, headless help, and sanitized credential state. A real smoke test may incur provider usage and must be explicitly authorized with an appropriate cost limit.

For Codex authentication modes and account restrictions, see [Codex authentication and compliance](/security-operations/security/authentication-compliance). For the configuration contract, see [Agent CLI configuration](/agents/cli-configuration).

## Verified development manifest

The runtime manifest accepts exactly:

```text
Codex CLI: codex-cli 0.153.4
OpenCode: 1.18.3
Cursor Agent: 2026.09.10-fd3934a
```

An upgrade is a reviewed code change to the manifest, provider fixtures,
provisioning, automated checks, documentation, and authenticated smoke evidence.
