# Agent CLI provisioning

The Action runs one selected external CLI. If its default executable is already available, the Action checks its version against the provider's current official release. When a newer stable release is confirmed, it installs that release into a private directory and uses it for this job. If the release cannot be checked, it uses the installed CLI. If the default command is absent, it installs only that provider's official CLI privately. A custom `agent-executable` must already exist and is always used as selected. No runner installation or persistent PATH is modified. Every selected CLI must report a non-empty version and pass the guarded executable and command checks before an agent task runs.

| Runtime | Default command | Official source when missing |
| --- | --- | --- |
| Codex | `codex` | [OpenAI standalone installer](https://learn.chatgpt.com/docs/codex/cli), Unix shell or Windows PowerShell |
| OpenCode | `opencode` | [OpenCode installer](https://opencode.ai/docs) on Unix; official GitHub release archive on Windows |
| Cursor | `agent` | [Cursor CLI installer](https://cursor.com/docs/cli/installation) on Unix; official Cursor archive described by its Windows installer |

The six distributed agent workflows do not run `actions/setup-node`, pnpm, or npm. GitHub Actions supplies the Node runtime for the bundled JavaScript Action. Development, CI, documentation, and package workflows still use their own Node toolchain. The provider installers receive a minimal environment without GitHub tokens or model credentials. The Action does not run unselected installers or send prompts through an installer.

Installer downloads and Unix shells use fixed system executable paths. Installer children receive a system-only `PATH`, so a workflow-added directory cannot replace `curl`, `sh`, `bash`, or a helper called by an official installer. On Windows, the Action validates and captures the runner's system directory at startup, including a Windows installation on another drive. Later environment changes cannot redirect `taskkill.exe`, PowerShell, curl, or the installer PATH.

The official Unix Codex installer exposes its command through links to a release stored under its private `CODEX_HOME`. The Action accepts that layout only while every link stays inside the new private installation directory and resolves to an executable file. A link outside that directory or a missing target fails installation and removes the temporary files.

Direct downloads are bounded before any bytes are written to disk: installer scripts to 1 MiB, release metadata to 2 MiB, and archives to 256 MiB. An empty, oversized, or failed transfer leaves no partial installer artifact. The official installer may perform its own further downloads after its script starts; those remain under that provider's installer behavior.

On Windows, a native provider executable runs directly. The Cursor PowerShell installer normally changes the user PATH and replaces a user installation; the Action instead reads its official download address and extracts the official archive inside the private job directory. OpenCode likewise uses its official release archive. Existing npm `.cmd` wrappers remain supported only when their package entrypoint and a separate trusted Node executable pass the read-only ACL checks, including their containing directories and ancestors. Agent arguments and prompts never go through `cmd.exe`.

No exact CLI version is pinned by the Action. The reviewed identities in the manifest are historical smoke baselines, not installation requirements. The update check uses the [Codex stable release channel](https://releases.openai.com/codex/channels/latest), [OpenCode releases](https://github.com/anomalyco/opencode/releases/latest), or the [Cursor platform installer](https://cursor.com/install). A version that cannot be compared is kept as installed; a failed confirmed update blocks the task before execution. The Action never retries an already-started agent task with a different CLI. Provider self-update commands are not used because they can change the runner's persistent installation or invoke its original package manager.

Presence and `--version` do not prove the selected model or account works; operators must verify those separately with an authorized smoke run. A missing credential, unsafe executable, unsupported command surface, or failed installation stops the selected task without switching providers. Process exit diagnostics expose only fixed categories such as reported model or authentication failure; raw provider stderr remains suppressed because it may contain secrets.

If an official installation finishes but its executable fails validation, the Action log includes the `official-installed-file` stage and a closed reason such as `missing-file`, `unsafe-link`, `acl-hardening`, `acl-ancestor`, `acl-file`, or `acl-inspection`. These identify the failed local check without printing installer output, paths, account names, ACL contents, or credentials. An ACL reason requires inspecting the runner configuration and a fresh Action check; it does not mean the agent task ran.

Older setups may retain an `AGENT_PROVISIONING` repository Variable. The current Action ignores it; it can be removed during normal configuration cleanup. The setup assistant no longer offers that choice.

## Credential scope

Map the selected provider credential only on the Copilot Action step. The Action never copies local OAuth files to a hosted runner. A controlled self-hosted Codex session can be used where its owner authorizes it; otherwise supply the relevant Secret. Do not put tokens in action inputs, command arguments, prompts, repository files, or logs.

## Read-only verification

From the repository root, `node scripts/verify-agent-clis.cjs` checks executable availability, help, version, and sanitized credential state. A help or version check does not send a model request. On Windows it validates native binaries or safely resolves an existing npm shim without invoking `cmd.exe`.

Windows agent support remains open until isolated hosted and self-hosted fixture jobs pass and the runner owner reviews ACLs, private artifact cleanup, cancellation, and the intended model/account. Do not use a credential-bearing test dispatch without authorization. See [Agent CLI runners](/security-operations/operations/cli-runners) and [Runtime selection](/agents/runtime-selection).
