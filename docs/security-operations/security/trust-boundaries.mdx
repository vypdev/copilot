# GitHub Actions trust boundaries

Treat workflow events as different trust zones:

| Event | Code source | Credential policy |
| --- | --- | --- |
| `push` to protected branches | Repository-controlled | Credentials MAY be available after protection checks |
| `pull_request` from a fork | Attacker-controlled merge commit | Secrets and write permissions MUST be unavailable |
| `pull_request_target` | Base workflow, untrusted PR data | MUST NOT check out and execute the PR code with secrets |
| `issue_comment` | User-controlled text | Authorization MUST run before any write-capable agent |

Self-hosted runners MUST be isolated, ephemeral where possible, and cleaned after agent execution. Agent prompts MUST treat repository content and comments as untrusted data.
