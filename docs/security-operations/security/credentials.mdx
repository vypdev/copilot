# Credentials

Credentials are references, not configuration values. They MUST be injected by
the runner environment and MUST NOT appear in action inputs, ordinary command
arguments, questionnaire state, plans, repository files, comments, reports, or
logs. Interactive setup accepts a value only through masked secret input and
keeps it memory-only; unattended `--secret`/`--workflow-pat` values are explicit
automation escape hatches that can be visible in process listings or shell
history.

Doctor is composed only with credential-health query authority. It may dispatch
an already-installed health workflow, but it cannot bootstrap, create, replace,
or delete that workflow; temporary health-workflow bootstrap belongs only to
setup.

An expression that references a protected Secret, such as `${{ secrets.CURSOR_API_KEY }}`,
is safe to keep in workflow YAML; the prohibition applies to the literal credential
value, not to the Secret reference.

| Runtime | Accepted reference | Prohibited export |
| --- | --- | --- |
| OpenCode | Provider-specific environment credential or controlled local login | OAuth/session files in CI |
| Codex | `CODEX_API_KEY` or local session on a controlled self-hosted runner | Personal session tokens in hosted CI |
| Cursor | `CURSOR_API_KEY` | Literal API key value in workflow YAML; `${{ secrets.CURSOR_API_KEY }}` is the supported reference |

Authentication preflight MUST fail closed when the selected runtime has no usable credential reference. A binary existing on `PATH` is not authentication evidence.

See [Codex authentication and compliance](/security-operations/security/authentication-compliance) for the account and terms matrix.

## Retaining organization credentials

Organization reuse and batch setup keep existing effective Secret bindings.
Their values are never read, copied, exported, logged or upserted. Metadata is
not proof of validity or full permissions. A repository override still shadows
the organization binding. Missing required bindings block that target instead
of silently rotating a shared credential.

Only explicitly reviewed selected-repository access is added to an existing
shared resource. Its value, visibility and other memberships remain unchanged.
Temporary permission probes are separate disposable resources with collision
checks, private names and cleanup receipts; their final review warns that GitHub
Secret writes are upserts without an atomic create-only guarantee. Pending
cleanup stops installation. Revoke the temporary operator PAT yourself when done.
