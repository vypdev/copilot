# Self-hosted runners

A self-hosted runner that can access agent credentials MUST be dedicated or isolated from unrelated workloads. Operators MUST:

- restrict repository and organization access;
- prevent untrusted fork jobs from selecting the runner;
- patch the operating system and CLIs;
- remove workspaces and transient logs after runs;
- restrict outbound network access where feasible;
- audit runner labels and permissions;
- keep local session files outside repository workspaces.

The compact Copilot comment callbacks require GitHub Actions runner **2.336.0+**
and platform support for self-repository references. Their reusable coordinator
keeps the Action on the called workflow's exact commit. Setup retains self-hosted
labels and groups in the call's `with.runs-on` JSON; it does not change group
access or prove capacity. See [comment workflow upgrades](/security-operations/operations/upgrade-rollback#upgrade-an-existing-copilot-repository).

A shared persistent runner is not equivalent to an ephemeral trusted runner.

The platform smoke jobs use the local pnpm store and disable automatic
dependency-cache backup. Each platform installs pnpm in its own job directory.
See the [setup-node cache inputs](https://github.com/actions/setup-node#usage).

In `vypdev/copilot`, `CI Check` uses the `vypdev` runner group with
`self-hosted`, `codex` and `Linux` labels. It runs for same-repository PRs,
pushes to `master` and manual dispatches. Static checks, package build and
smoke, and tests with coverage can occupy three runners at once. Each uses its
own checkout and the runner's local pnpm store. The required `CI Check` job
then records all three conclusions without checking out code. Every job
excludes fork PRs before runner assignment. The source repository has no
active merge queue. Restore a compatible required check on a suitably isolated runner
before enabling a queue.

Run the setup fixture matrix manually from protected `master`. It exercises
Ubuntu, Windows and macOS on self-hosted runners, using Windows services
without the `codex` label. A Linux runner needs the Firefox ESR system
libraries preinstalled. The workflow checks the pinned Firefox binary without
installing system packages. Windows coverage is preserved as a short-lived
artifact and exported only with `upload_windows_coverage=true`. The separate
Codex service smoke remains Ubuntu-only until macOS capacity is restored.
A queued or skipped platform job is unverified.

The only GitHub-hosted jobs in this repository are issue-event admission and
release/hotfix npm publication. [npm Trusted Publishing](https://docs.npmjs.com/trusted-publishers/#supported-cicd-providers)
requires a GitHub-hosted runner for OIDC. Deployment preflight and credential
health use the self-hosted Linux pool. Setup templates retain their consumer
defaults and accept runner choices from each project.

RepoWise obtains a complete Python 3.12 distribution via
`actions/setup-python`, creates its virtual environment and reports in
run-specific temporary directories, and removes them after artifact upload.
Its runner needs a writable Actions tool cache and GNU `/usr/bin/time` for phase
RSS evidence. The isolated Python suite verifies the pinned history adapter before
analysis; phase time/virtual-memory caps and a 40-minute job bound the run.
The workflow does not install
Ubuntu system packages. RepoWise runs only through manual dispatch on
`[self-hosted, codex, Linux]`, using the reviewed repository ref selected by the
maintainer. It is optional and must not be required by branch protections or
rulesets. It no longer consumes this pool on every PR or push. See
[testing and manual analysis](/development/testing) for launch instructions,
revision evidence, scan limits, artifacts, and retry behavior.

The `[self-hosted, codex]` pool routes agent jobs to macOS and Ubuntu. Windows
services MUST omit `codex` on registration; recreate existing registrations to
remove it. The four Windows services remain available for other jobs. Install
Git and Bash on runners selected by the installed Bash workflows. Distributed
agent workflows use the embedded Action Node; development and packaging jobs
keep their own toolchain.

**Codex no soportado en runners Windows ejecutados como servicio.** The
session-0 service limitation does not claim that interactive Windows fails.
Do not deploy a patched CLI, disable its sandbox, or require interactive login
as recovery. See [Codex runtime support](/agents/codex-openai).

The JavaScript Action runs under the runner's embedded Node. Missing agent CLIs and confirmed newer official releases use standalone installers and release archives in private job directories. Self-update commands are not run against installed CLIs. Existing npm `.cmd` shims on Windows still need a separately trusted Node executable; native installed CLIs do not.
Verify each operating system with an actual runner job before
claiming Action-wide compatibility; the platform matrix exercises isolated
setup and agent fixture paths. In particular, inspect timeout and cancellation of
agent child processes on Windows separately from POSIX process-group behavior.

The Action passes agent children an allowlisted runtime environment plus only the credential selected for that provider; unrelated GitHub, cloud, database, and PAT variables are not inherited. Codex review capabilities are forced to `--sandbox read-only --ignore-user-config --ignore-rules`; fixer capabilities use `workspace-write`, with network and extra writable roots disabled. Cursor receives a per-invocation configuration/home with sandboxing and default-deny network policy. OpenCode receives a pure, inline default-deny permission profile with shell, task, skill, web, and external-directory tools disabled. Dangerous bypass flags are rejected for every runtime. These controls complement rather than replace runner/container isolation.

Configured verification commands also receive a temporary `HOME` and credential-free allowlisted environment. They are repository processes, not model tools, so the runner must still prevent them from reading unrelated host paths through OS-level isolation.

Timeout and cancellation terminate the complete POSIX process group, with a bounded graceful period before a forced kill, so abandoned CLI descendants do not occupy the runner indefinitely.

Windows PowerShell 5.1 can spend the first invocation discovering cmdlet modules
inside a fresh isolated profile. Bounded native shell fixtures explicitly import
the absolute system `Microsoft.PowerShell.Utility.psd1` manifest before hashing.
Their timeout stays unchanged. This avoids depending on a host's warm module
cache and keeps the runtime's private profile and checkout-cleanliness checks.
A runner-disconnection annotation is an infrastructure failure; passing tests on
another platform does not turn that job into a successful smoke run.

The manual `Copilot - Runner diagnostics` workflow retains only its Linux
Codex prerequisite job. General Windows PowerShell startup diagnostics and
platform fixtures remain separate and do not invoke real Codex. CLI or
model success is distinct from a verified tool read, edit, or command. A model
reply and a setup marker cannot certify sandbox tools. No new Windows-service
Codex acceptance run is required or scheduled.

The Linux diagnostic now prepares official standalone Codex0.171.0 privately
in the same job as Node24.21.0. It checks the fixed distribution checksum and
actual executable bytes before probes. It retains the full official package,
including adjacent bwrap/rg and execution helpers, and checks its fixed layout
and resource identities before the CLI version check. A matching standalone
executable/version alone is insufficient when resources are missing. The
runner's global installation stays untouched. Start `Copilot - Runner diagnostics` on the reviewed source revision.
Manual dispatch uses the existing trusted-operator contract: repository writers
can already run selected branch code through source CI. Choose the exact reviewed
revision after its source checks and review; arbitrary selected branch code is
not isolated by a read-only GitHub token or disabled checkout credentials. The
workflow adds no fork-event admission or runner privilege. Persistent runner
isolation remains an operator requirement.

Its Job Summary shows each actual exit/signal and links through the run to the
`linux-sandbox-prerequisites` artifact. Download the receipt within its one-day
retention period when retaining investigation evidence.

The host `sandbox` command uses root configuration overrides and a new private
HOME/CODEX_HOME; `exec`-only ignore options do not apply to it. An
`unexpected argument` result is a diagnostic invocation failure before sandbox
execution. Preserve it and correct the source command before a changed attempt.

The schemaVersion4 receipt retains ten observations. Five check namespace or
bubblewrap execution and empty-environment versus PATH-only Codex startup.
Namespace commands require their actual Node output witness and exit0.
Specified witnesses must match the captured channel exactly: added spaces, tabs,
newlines or Unicode whitespace produce `assertion-mismatch`. The diagnostic
does not trim those markers. A package metadata failure retains the closed
`package-metadata` phase in the artifact; preparation stays failed, all ten
probes stay not-run and owned cleanup remains visible. Three
controls then run the same harmless Node payload directly, through bubblewrap
and through Codex. Each requires both output markers and exit37. Only those
three named execution-transport rows expect37; ordinary rows still require0.
The summary shows expected and actual exit separately. Silent success does not
prove that the enclosed command ran.

The owned Node payloads write their evidence directly to stdout/stderr file
descriptors. Restricted socket introspection can make Node silently discard its
ordinary streams even though the command returns its expected exit. The receipt
and summary declare `node-fd-write-sync` and mark Node stream compatibility as
not measured. This measurement method does not relax sandbox/network policy or
certify arbitrary Node tools, SDK/model tools or qualification. Preserve earlier
schema1/2/3 receipts under their original output methods.

The report retains the first65,536 raw bytes of each output channel as a
contiguous prefix and decodes that prefix once. Valid UTF8 split across child
chunks survives; invalid bytes or a character cut by the byte limit can appear
as replacement characters. `outputTextEncoding=utf8-replacement` declares that
view. `outputCapture` separately records observed/retained byte counts and raw
SHA256s for stdout and stderr. Observed hashes include all chunks delivered
through close, even after truncation starts termination; retained hashes cover
the bounded prefix. The older stdout/stderr hash fields still identify decoded
text before privacy projection. Raw bytes are not exposed to evade projection.
Truncated output remains incomplete and cannot establish sandbox acceptance.

All three independent transport commands must close before cleanup. If any
fails or is unavailable, the owned read/hash and write-denial probes stay
`not-run (execution-unverified)` and collection is incomplete. A verified read
must match its trusted digest; a successful denial must produce the expected
result and leave the canary absent. Missing output is null; actual empty output
has an empty-byte hash. Cancellation before spawn and executable launch failure
leave both channels, their hashes and capture metadata null. A later error after
a successful spawn preserves actual captured bytes.

The diagnostic job allows15minutes for preparation, collection and artifact
retention. The fixed download/command/termination/Engine timeouts remain
60s/20s/1s/3s. Their nominal sequential allowance is294s, leaving more than ten
minutes for checkout, Node setup, hashing and retention; this margin is not a
guarantee against stalled host I/O. No model or research limit changes.

The report also observes the bounded fixed system bwrap
file's hash, format, ownership and mode; metadata alone never proves execution.
An optional local Engine version observation is separate and creates no
image/container/workload.

The Engine row distinguishes a missing socket, denied socket access and a
refused connection when the job's actual request provides one of those known
causes. The receipt adds only the closed `connectionFailure` tag; raw error
codes, messages and paths are excluded. Unknown errors and older receipts stay
cause-unknown. A forged value cannot appear as summary text.

`Engine: unavailable (socket missing)` describes the fixed job socket query;
it does not establish that Docker is uninstalled on the host. Inspect the
existing runner's local Unix-socket configuration and the job's access before
preparing qualification. Nothing changes permissions automatically. A version
response appears as `version metadata observed; workload not verified` and
still does not prove the contained SDK runtime or model-tool isolation.

Preparation failure leaves probes `not-run`. Missing tools are `unavailable`;
nonzero/signal/mismatched/truncated observations are failures. Cancellation
settles the owned command and marks remaining probes `not-run`; cleanup failure
stays visible. Cancellation during the final Engine observation or cleanup also
leaves the collection incomplete and fails the job. The summary shows collection
completeness and cleanup independently of earlier passing rows. Adapter startup
errors retain a failed-preparation receipt; private-root initialization cleans
only its owned directory and records any cleanup uncertainty. Engine identities
require string version fields. Preserve the receipt and fix the demonstrated cause before a
changed attempt. A completed diagnostic job means observations were collected,
including negatives; its green status alone does not certify a sandbox.

The report projects private/account paths and uses a private credential-free
HOME/config. It introduces no privilege, runner registration or global setting
change. These model-free command probes do not prove SDK/model tools, managed
credential/oracle exclusion, native qualification controls or the174/42campaigns.
Those require their own exact source/runtime evidence and committed admission.

## Credential-health source selection

The source policy selected for integration in [#979](https://github.com/vypdev/copilot/issues/979)
explicitly routes source health jobs to group `vypdev` with `self-hosted`, `codex`
and `Linux` labels. Its default-ref/workflow and actor selector runs before a
job receives a runner; unselected checks stay disabled. Preserve the existing
hosted exceptions for event admission/npm OIDC and all consumer runner defaults.

This routing does not establish runner isolation or externally enforced workflow
access. Organization runner-group evidence is unavailable (403). A collaborator
who can change workflow code can remove its local condition; the policy review
must treat that privilege explicitly. The inspected default revision still has
the old hosted health workflow, so neither a develop change nor this source decision
proves adoption. Inspect native actor/ref and selected checks when a run skips;
use an explicit default-branch retry after reviewing the missing condition.
