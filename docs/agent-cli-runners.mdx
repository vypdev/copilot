# Agent CLI runners

Copilot uses one execution contract for all supported agents: a provider-specific headless CLI receives the prompt on standard input and returns its response on standard output.

| Provider | Headless command | Credential reference |
| --- | --- | --- |
| OpenCode | `opencode run` | Provider-specific API key in the workflow environment |
| Codex | `codex exec --ephemeral --skip-git-repo-check -` | `CODEX_ACCESS_TOKEN`, `OPENAI_API_KEY`, or a local ChatGPT session in `CODEX_HOME/auth.json` |
| Cursor | `agent -p --output-format text -` | `CURSOR_API_KEY` |

There is deliberately no transport setting, server URL, managed server lifecycle, or provider fallback. If the selected provider is unavailable or fails, the run fails closed and no other agent is attempted.

## Runner provisioning

Provision the CLIs on the runner before enabling the workflow. Installation is intentionally outside the action bundle so the action remains a small application adapter and does not download executables during a run.

The provisioning job or image must:

1. install the exact versions selected by the organization;
2. expose the binaries as `opencode`, `codex`, and `agent`;
3. authenticate through environment-backed secrets or the provider's non-interactive login mechanism;
4. run `node scripts/verify-agent-clis.cjs`;
5. fail before invoking Copilot when the selected provider is unavailable.

Do not put API keys in repository files, action inputs, workflow YAML, or command strings. The checker reports only executable and credential-reference state and never prints secret values.

## Configuration

The only agent selection inputs are:

```yaml
agent-provider: ${{ vars.AGENT_PROVIDER }}
agent-model-provider: ${{ vars.AGENT_MODEL_PROVIDER }}
agent-model: ${{ vars.AGENT_MODEL }}
agent-command: ${{ vars.AGENT_COMMAND }}
```

`agent-command` is optional. When omitted, Copilot derives the safe provider default shown in the table above. The provider and command are validated together; a command for another provider is rejected.

Example provider selection:

```yaml
with:
  agent-provider: codex
  agent-model-provider: openai
  agent-model: gpt-5-codex
  agent-command: codex exec --ephemeral --skip-git-repo-check -
env:
  CODEX_ACCESS_TOKEN: ${{ secrets.CODEX_ACCESS_TOKEN }}
```

## Verification

From the repository root:

```bash
node scripts/verify-agent-clis.cjs
```

A provider is operational only when its executable, headless help invocation, credential reference, and non-production smoke execution succeed. Verification must be performed on the exact runner image used by the workflow.
