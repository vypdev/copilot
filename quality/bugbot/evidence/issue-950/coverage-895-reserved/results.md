V8 13.6.233.17-node.53, pnpm 10.34.0, Playwright 1.64.1 and
Chromium headless shell 156.0.8078.4. Installation used the frozen
lockfile and disabled install scripts. `pnpm check` passed in both
checkouts. Both then ran the repository's unmodified `pnpm test`,
which runs `vitest run --coverage` and invokes
`node --test tests/coverage-evidence.test.mjs` only if Vitest exits zero.
The [evaluator record](evaluation.json) contains the report hashes,

The [mutation](mutation.patch) touches only `vitest.config.ts`.
Vitest reports 50% branch coverage for the leaked story. With only
the exclusion changed, the normal threshold stopped the pipeline
before the inventory. The committed mutation keeps branch coverage
at 100% for all other files and gives only the leaked story a 50%
branch threshold. The inventory and the test command remain byte
identical to the original. Vitest exits zero and the inventory exits
one. The JSON summary was generated by the real V8 reporter.

The extra entry has 2/2 lines, 13/13 statements, 7/7 functions and
2/4 branches. The totals move from 1,234/1,234 to 1,236/1,238 branches.
The evaluator verifies that every runtime entry is identical and that
the aggregate delta is exactly the leaked story's contribution.
An in-memory control removes that entry and restores the aggregate
from the original. The unchanged inventory then passes. That control
does not modify either generated report.

| Resolved dependency | Version | Cited evidence |

| `@vitest/istanbul-lib-report` | 2.1.0 | Write the default JSON summary with the aggregate and one key per covered file. |

The SDD's first profile allows already resolved dependency evidence.
This control uses the [lock-authenticated archive precedent](../on-demand/prepare.py).
The application resolves the package entry from the clean frozen pnpm
installation, checks the importer or parent snapshot and the package's
version, verifies the archive SHA-512 against the reviewed lockfile,
and checks byte equality for the resolved entries and fragments.
It also checks Vitest's V8 dispatch and the reporter's built-in mapping.
Acquisition and archive authentication happen once in fixture preparation.
Only the bounded, read-only fragments enter the verifier packet.

The [simulated delivery](dependency-control.json) passed in both
trees through the existing receipt and final-citation validation.
Shared provenance in the wire packet records operation, candidate,
head, tree, lock blob and the resolved package versions and
integrities. Each fragment keeps its full bound receipt in the
application. The fake verifier receives source only and cites all
ten dependency fragments and the four Git fragments in each final
packet. The controls reject wrong version, lockfile, file, revision
and foreign citation. The Git reader keeps its existing 80-line,
4,400-byte fragment caps and cumulative source limits. The dependency
packet stays within 9,000 bytes and both full packets stay within
15,500 bytes (13,579 original and 14,088 mutant). The prototype does not grant dynamic npm, filesystem or
execution access to a verifier. The future runner must retain this
prepared-dependency route.

## Reproduce

Use Node 24.20.0, Corepack, Git, tar and a local ha-ui Git clone with
the original head and comparison base. Run these commands from this
evidence directory with absolute paths.

```sh
sh prepare.sh "$HA_UI_GIT" "$LAB"
sh replay.sh "$LAB" > "$LAB/evaluation.json"
mkdir "$LAB/archives"
(cd "$LAB/archives" && npm pack --ignore-scripts --registry https://registry.npmjs.org \
  vitest@5.1.0 @vitest/coverage-v8@5.1.0 @storybook/addon-vitest@10.6.5 @vitest/istanbul-lib-report@2.1.0)
node dependency-control.cjs "$LAB" "$LAB/archives" > "$LAB/dependency-control.json"
cmp "$LAB/dependency-control.json" dependency-control.json
```

The raw coverage hash includes absolute report keys and can vary
with the checkout directory. Compare the normalized inventory,
metrics, exclusions and process outcomes to reproduce the conclusion.
