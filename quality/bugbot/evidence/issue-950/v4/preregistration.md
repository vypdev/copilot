## Fair execution and boundaries

| Arm | Detection in full review | Verification |
|---|---|---|
| Current | Unchanged audited production prompt, medium effort, read-only checkout and native partition retries | Gated production literal verifier with its existing tools and medium effort |
| Context | Production detector with the shared reachability and causal-anchor guidance, medium effort | Fresh closed verifier with the candidate and bounded canonical original hunk |
| Source/CI | Same experimental detector response as Context | Same closed verifier, plus project receipts and corresponding citation IDs |

The two experimental arms reuse the same raw detector response per model,
subject, repetition and attempt after verifying prompt/schema/config identity.
Current has its own unchanged detector. The unit hashes fix interleaving, with
three concurrent Luna units and six Sol units. Arms execute in preassigned
order within a unit. Credit shared inspection cost and time to each arm for a
route comparison and deduplicate it for campaign totals. This makes full review
an end-to-end comparison with the current route and a paired evidence-only
comparison between the experimental arms. Replay isolates the verifier with
identical frozen candidates. Keep the existing SDK audit revision and Codex CLI.

Host adapters attest immutable trees, diffs, evidence blobs and the applicable
dependency lock. The audited production orchestrator uses a read-only detached
checkout. Closed sessions have a fresh directory, disabled shell, MCP, web,
plugins and skill access, no checkout and no GitHub credentials. Every mutation
port throws and is counted. Any attempted write invalidates the trial.
Malformed verdict, invalid citation, fabricated anchor or interrupted aggregate
cannot produce an actionable finding.

Keep the 90-second verifier subject wall ceiling, 32,768 gross input and
4,096 output tokens, with four total closed calls. One call may wait up to 48
seconds for a terminal turn. Retry once only after a timeout with zero completed
turns and no tool event, when at least 15 seconds, one call and the token
reservation remain. Retry in a new session. Reserve 10,000 scheduling tokens for
unmetered timeout input and another 7,400 for a new call. An unmetered attempt
never counts as measured zero. Any unknown usage prevents overhead
qualification. Failed and inconclusive rows remain in the ledger. At a valid
completed turn allow a 900 ms process exit grace within the subject limit.
The request cap is 21,500 UTF-8 bytes, with 15,500 for the packet and 2,800 for
the diff. A verified source path in the packet is required for Source/CI.
