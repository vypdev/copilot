## Independently reviewed bootstrap and manifest

The supported qualification route starts outside the source checkout. An operator
must select an independently reviewed bootstrap commit and SHA-256, materialize
its Git blob with trusted operating-system Git, verify that SHA-256 **before**
starting trusted Node, and clear NODE_OPTIONS/NODE_PATH. Running a working-tree
entrypoint or verifier directly is not qualification admission. Neither a
self-declared manifest nor a receipt generated by that checkout establishes
this trust anchor; a compromised host or substituted approved digest is outside
this local proof.

The bootstrap takes repository, reviewed plan commit, repository-relative plan
path, externally reviewed plan SHA-256, externally reviewed bootstrap SHA-256,
mode (`corpus`, `full-review`, `normal-flow`), then that mode's arguments. It
checks the immutable committed plan and the complete fixed driver inventory
against their reviewed bytes before importing any driver or helper. It rejects
changed physical drivers and symlinks, uses a sterile local Git clone to
materialize the committed revision, and loads the verifier only from there.
It verifies original source/runtime, copies physical dependencies to the private
source tree, verifies the copy again, and executes that immutable entrypoint.
The disposable directory is not part of the stable recorded identity. Explicit
signals are forwarded; no investigation time/turn/read/token ceiling is added.

Normal-flow authenticates its exact committed manifest and externally selected
digest before using runtime fields, including the version probe. The bootstrap
records its own reviewed digest and the reviewed plan revision/path/digest;
corpus and full-review provenance compare those same values. It forces the child
production mode to disabled and preserves dry-run publication. An auxiliary
Python used by old diagnostic workflow-input plans now needs explicit executable
and digest pins; it cannot be selected from an unchecked environment override.
